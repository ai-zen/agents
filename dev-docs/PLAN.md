## 这个文件里只许写两样东西

**需求**：`PRD.md` 里的一条，做完之前一直在表上。**专项**：一件能独立交付的工程事项，说得出交付物是什么。

其余一律不许写进来：代码审计（某个文件缺什么、某个方法没人调、某个导出还没换）、重构念头、临时发现、待观察项、风险评估，以及任何答不出「这是哪条需求」的东西。发现代码缺陷只有两条路——当场修掉，或者它让某条需求做不到时归到那一条的「怎么算做到了」里；不许为此新开一行。

> 判据：这一行能不能翻成 `PRD.md` 的一句话需求，或者一件说得出交付物的专项？不能就删。
> 第二道判据：把这一行贴给没看过代码的人，他知不知道会看见什么变化？不知道就重写，而不是加注释解释。

## 顺序

前三行是专项：它们先把地基铺好，后面每一行都站在上面。地基没铺完，不做第四行以后的事 —— 那会在错的地方砌墙，等地基一换，全部重写。

| # | 做什么 | 怎么算做到了 |
|---|---|---|
| 1 | **专项：sdk 的运行时** —— 由它登记常驻 agent、按目录持有能力容器、把一条消息递给另一个 agent、发出「谁出现了 / 谁没了」 | 不 import 宿主，同一进程里：起一个 agent 并收到完整流；起两个 agent，A 递一条给 B、B 收到并回话；开出一段平级会话，两边互相说话；两段会话共用一个能力容器，全部结束后容器被拆掉。把宿主那一侧的实现换成空实现，上面四条一条都不变 |
| 2 | **专项：core 的观测与持久化切点** —— 序号、定稿、一趟请求的开始与结束、对象消失前的收尾点、订阅者抛错不影响被观察者 | 订阅者按序号能判出重复与缺口；一条消息有「这一版是终版」这条事实；一趟请求有边界可挂；对象消失前能拿到最后一批事实，之后不再有事件；订阅者故意抛错，agent 照常跑完 |
| 3 | **专项：宿主退化成薄壳** —— 装配、登记、投递、能力容器全在运行时；宿主只留库、连接、凭证、通知、素材、文案 | 宿主里找不出「agent 怎么装起来」「谁活着」「容器什么时候拆」这三件事；打开会话、投递、事件推送的行为一字不变（跨进程用例一直是绿的） |
| 4 | **平级会话与 agent 之间的通信**：模型能另开一段正常会话，双向递话，结果靠对方投回来；agent 建的会话没有创建会话的工具；用户能看、能暂停、能杀 | 界面上出现那段会话，它回的话落在开它的那段里；没有一层套一层的路 |
| 5 | **项目面**：只走显式添加、能列、能删（连带它名下的会话，删前说清代价，目录本身永不碰）；位置不可变；名字先取创建时间 | 从界面上建一个项目、看见它名下的会话、删它之前看见「会连带删掉什么」 |
| 6 | **会话上可改的那几样**：模型、思考档位、两条阈值、自动交接开关、置顶、改名；以及撤回到某条自己说过的话之前（其后硬删、内容回填输入框） | 每一项都改得动、改完下一次请求就按新的来；撤回之后那段历史真的没了、那句话回到输入框 |
| 7 | **配置一处管完全部**：端点、模型、图片模型、助手与 subagent、默认项、全局两项、中断策略两项、思考档位表；出厂托管每次启动与出厂对齐；恢复出厂；删之前说清谁还指着它；改完即生效 | 配置在一个地方改完，下一句话就按新配置走；删一个被别处指着的条目时先看见「谁还指着它」 |
| 8 | **MCP 的清单与启停**：列出五层合并后的结果、每条属于哪一层、哪条被更近的一层停用了；停用就断、启用就重连 | 界面上看得见每个服务器并开关它，开关立刻生效，看得出一条为什么没在跑 |
| 9 | **附件**：一张最多 20MB、一条最多 4 张，超限报错不截断；媒体原样回去 | 贴一张图能发出去；超限那一下当场被拒，而不是发出去等端点回错 |
| 10 | **两条阈值**：软线越线问用户一次（自交接 / 独立交接 / 不交接），硬线越线这次请求不发，交接那一次硬线让路，这道线罩住 subagent 与孙级 | 撞软线时出现一道三选题，答「不交接」之后不再问；撞硬线当场被拒 |
| 11 | **关掉再打开**：关闭宿主是显式动作（命令 + 二次确认）；重启之后所有会话都是死的，只有人的话能重新开始；记忆与排队区都还在 | 关掉再打开：历史与没被处理的那几句话都在，没有一段会话自己跑起来 |
| 12 | **升级**：宿主验「这一版拿得到」、写 pin、以升级为理由退出，由启动方式重拉；装包与拉起不在宿主里 | 点一次升级，宿主换到新版；升不上去时说得清是哪一段没成 |
| 13 | **客户端能用**：终端与桌面连得上新宿主，并把上面这些事做完 | 从连接屏走一遍：连上、建项目、建会话、发话、看图、改配置、交接、关掉 |

## 已经拍过、不要重开的

- **运行时在 sdk，宿主只负责连接、持久化与客户端杂项。** 判据是「没有宿主，用 `core` + `sdk` 能不能组装出能跑的事件驱动 agent、常驻 agent、互相通信的 agent」。做不到就说明分层错了，先改分层，不许用宿主去补。
- **库只是持久化，只为下一次恢复。** 有活物时内存是事实，库里那份可能滞后、也可能压根没有；没有活物了才读库，那时库就是它的全部。
- **观察是旁路，拦截用钩子。** 订阅者抛错不能打断被观察的对象；能拒的钩子 fail-closed、返回判决，两者不许共用一个口。
- **每条连接都要凭证，凭证只从握手帧上来。** 不判来路、没有「回环地址免检」：本机的无感来自 `run/token` 里那一串被客户端读走，不是来自地址。对外实例不写那个文件，凭证由 `agents-host token create` 造出来再分发。吊销只影响以后能不能连上，不回头断开已经握过手的连接。
- **凭证不进契约面。** 客户端只有「记住密码 + 连接管理」；创建 / 列出 / 吊销是宿主命令行的事。这条 2026-11-13 拍过一次，重写时又被放回契约面一次 —— 别再放回去。
- **不做任何降级。** 申请哪个执行者就跑哪个，做不成 = 失败：开闸、退出交接状态、告诉用户失败。换成另一个执行者继续，会让一次失败的交接看起来像成功。注意区分：`summary` 作为**调用方显式选的执行者**不是降级（三选一的题面里就有它）。
- **没有旧版本，也没有旧库。** 表由各域的 `*Table(db)` 就地建；形状对不上就把库文件删掉重建。任何形式的版本递进都是在为一个不存在的处境兜底，而它自己的分支（补列、重建索引、判断列存不存在）每一处都是新的出错面。
- **题挂着时不挡发送。** 要不要因为一道没答的题把发送按钮按住，是客户端的事：它手上就有那道题，而宿主只知道「有这么一道题」却不知道界面上用户正打算做什么。`blocking` 仍进载荷——客户端靠它决定该不该按，而不是靠宿主替它拦。
- **交接不接 Skill。** 交接不是一种能力：把交接文档的模板放进用户可编辑的 Skill 目录，等于用户改一次 Skill 就意外改掉交接行为。用 SDK 内置的那份模板。
  连带一件要清：`ConfigManager.bootstrap()` 仍会释放 `<数据根>/skills/handoff/SKILL.md`，而没人读它。一份看起来是配置点、实质是死的文件，比没有它更糟——要么让 SDK 不再释放，要么先记在这里。

## 门禁

- `tsc --noEmit -p tsconfig.test.json` 通过；
- `npx vitest run` 通过，跑的是域内用例（不起端口、不写真实磁盘）；
- `npx vitest run --config vitest.e2e.config.ts` 通过，跑的是真的一套（真端口、真磁盘、真 WebSocket）；
- 提交信息一行标题说清改了什么，正文写「改前 / 改后 / 为什么」。

## 并行时的边界

同一波次的目录不重叠；跨域共用的单文件（`src/index.ts`、`app.ts`、`modules/events.ts`）由主 Agent 统一改。

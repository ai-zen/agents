## 这个文件里只许写两样东西

**需求**：`PRD.md` 里的一条，做完之前一直在表上。**专项**：一件能独立交付的工程事项，说得出交付物是什么。

其余一律不许写进来：代码审计（某个文件缺什么、某个方法没人调、某个导出还没换）、重构念头、临时发现、待观察项、风险评估，以及任何答不出「这是哪条需求」的东西。发现代码缺陷只有两条路——当场修掉，或者它让某条需求做不到时归到那一条的「怎么算做到了」里；不许为此新开一行。

> 判据：这一行能不能翻成 `PRD.md` 的一句话需求，或者一件说得出交付物的专项？不能就删。
> 第二道判据：把这一行贴给没看过代码的人，他知不知道会看见什么变化？不知道就重写，而不是加注释解释。

## 已经拍过、不要重开的

- **运行时在 sdk，宿主只负责连接、持久化与客户端杂项。** 判据是「没有宿主，用 `core` + `sdk` 能不能组装出能跑的事件驱动 agent、常驻 agent、互相通信的 agent」。做不到就说明分层错了，先改分层，不许用宿主去补。
- **平级会话不是第二期的功能，它就是运行时存在的理由。** 一段会话里的模型另开一段正常会话、两边互相递话 —— 这件事在 sdk 里跑不起来，运行时就是一张没人用的登记表；反过来，运行时没有把自己交出去的用途，也就不该存在。
- **宿主只提供「跟客户端通信」的那一层。** 合并哪几层、出厂托管与恢复出厂、默认项解析、删除前「谁还指着它」、能力表、MCP 的连接与重连与退避 —— 全部是 sdk 算的，宿主只读写文件、转事件。判据：宿主里那段代码是不是只在「读写文件、转成事件」？一旦它在算「哪些配置有效」「该连哪个」，就是把 sdk 的事搬上来了。
- **停用不是一种功能，它是配置里那一条。** 把某个 MCP 服务器关掉，就是把它从配置里删掉或给它写上停用；「停用就断、启用就重连」是能力容器收到配置变更后的后果，不是另一个界面动作。
- **库只是持久化，只为下一次恢复。** 有活物时内存是事实，库里那份可能滞后、也可能压根没有；没有活物了才读库，那时库就是它的全部。
- **观察是旁路，拦截用钩子。** 订阅者抛错不能打断被观察的对象；能拒的钩子 fail-closed、返回判决，两者不许共用一个口。
- **每条连接都要凭证，凭证只从握手帧上来。** 不判来路、没有「回环地址免检」：本机的无感来自 `run/token` 里那一串被客户端读走，不是来自地址。对外实例不写那个文件，凭证由 `agents-host token create` 造出来再分发。吊销只影响以后能不能连上，不回头断开已经握过手的连接。
- **凭证不进契约面。** 客户端只有「记住密码 + 连接管理」；创建 / 列出 / 吊销是宿主命令行的事。这条 2026-11-13 拍过一次，重写时又被放回契约面一次 —— 别再放回去。
- **不做任何降级。** 申请哪个执行者就跑哪个，做不成 = 失败：开闸、退出交接状态、告诉用户失败。换成另一个执行者继续，会让一次失败的交接看起来像成功。注意区分：`summary` 作为**调用方显式选的执行者**不是降级（三选一的题面里就有它）。
- **没有旧版本，也没有旧库。** 表由各域的 `*Table(db)` 就地建；形状对不上就把库文件删掉重建。任何形式的版本递进都是在为一个不存在的处境兜底，而它自己的分支（补列、重建索引、判断列存不存在）每一处都是新的出错面。
- **题挂着时不挡发送。** 要不要因为一道没答的题把发送按钮按住，是客户端的事：它手上就有那道题，而宿主只知道「有这么一道题」却不知道界面上用户正打算做什么。`blocking` 仍进载荷——客户端靠它决定该不该按，而不是靠宿主替它拦。
- **交接不接 Skill。** 交接不是一种能力：把交接文档的模板放进用户可编辑的 Skill 目录，等于用户改一次 Skill 就意外改掉交接行为。用 SDK 内置的那份模板。
  连带一件要清：`ConfigManager.bootstrap()` 仍会释放 `<数据根>/skills/handoff/SKILL.md`，而没人读它。一份看起来是配置点、实质是死的文件，比没有它更糟——要么让 SDK 不再释放，要么先记在这里。
- **硬线不让路。** 交接那一次请求撞上硬线也照拦，要避免撞线就把阈值配得够宽（旧版那条「谁设的限谁让路」已作废，见 [`prd/05-control.md`](prd/05-control.md)）。

## 门禁

- `tsc --noEmit -p tsconfig.test.json` 通过；
- `npx vitest run` 通过，跑的是域内用例（不起端口、不写真实磁盘）；
- `npx vitest run --config vitest.e2e.config.ts` 通过，跑的是真的一套（真端口、真磁盘、真 WebSocket）；
- 提交信息一行标题说清改了什么，正文写「改前 / 改后 / 为什么」。

# 宿主实施顺序

需求见 `PRD.md`，技术规范见 `TRD.md`，结构与判据见 `../packages/host/ARCHITECTURE.md`，风格见 `../packages/host/STYLE.md`，术语见 `GLOSSARY.md`。

本文件只回答两件事：**哪条需求还没做到，怎么算做到了，先做哪一块。** 代码怎么写归 `ARCHITECTURE.md` 与 `STYLE.md`，不写在这里。旧 `src` 已整包退到 `../packages/host/src-bad`，只作行为参照。

## 这个文件里只许写两样东西

**需求**：`PRD.md` 里的一条，做完之前一直在表上。**专项**：一件能独立交付的工程事项，说得出交付物是什么（例如把客户端接到新宿主上）。

其余一律不许写进来：代码审计（某个文件缺什么、某个方法没人调、某个导出还没换）、重构念头、临时发现、待观察项、风险评估，以及任何答不出「这是哪条需求」的东西。发现代码缺陷只有两条路——当场修掉，或者它让某条需求做不到时归到那一条的「怎么算做到了」里；不许为此新开一行。

> 判据：这一行能不能翻成 `PRD.md` 的一句话需求，或者一件说得出交付物的专项？不能就删。
> 第二道判据：把这一行贴给没看过代码的人，他知不知道用户会看见什么变化？不知道就重写，而不是加注释解释。

## 还没做到的需求

每个「还没做到」都是一个用户能看见的缺口，不是一句代码审计。

| # | 需求 | 怎么算做到了 |
|---|---|---|
| 1 | **打开一段会话，同时拿到它的当下状态与全部历史消息**：有执行体就从它内存里读，没有执行体才读库；状态与消息一次取到 | 断线重连之后界面不是空的；把宿主关掉再打开，那些消息还在 |
| 2 | **项目只走显式添加**：能列出来、能删（删项目连带删它名下的会话，删前说清代价，目录本身永不碰）；位置不可变；名字先取创建时间 | 从界面上建一个项目、看见它名下的会话、删掉它时先看到「会连带删掉什么」 |
| 3 | **会话上可改的那几样**：模型、思考档位、交接阈值与防护阈值、自动交接开关、置顶、改名；**撤回**到某条自己说过的话之前（其后硬删、内容回填输入框） | 界面上每一项都改得动、改完下一次请求就按新的来；撤回之后那段历史真的没了、那句话回到输入框 |
| 4 | **配置一处管完全部**：端点、模型、图片模型、助手与 subagent、默认项、全局两项、中断策略两项、思考档位表；出厂托管的那批每次启动与出厂对齐；恢复出厂；删之前说清还有谁指着它；改完即生效 | 配置在一个地方改完，下一句话就按新配置走；删一个被别处指着的条目时先看见「谁还指着它」 |
| 5 | **MCP 服务器的清单与启停**：列出五层合并后的结果、每条属于哪一层、哪条被更近的一层停用了；停用就断、启用就重连 | 界面上看得见每个服务器并开关它，开关立刻生效，看得出一条为什么没在跑 |
| 6 | **附件**：一张最多 20MB、一条最多 4 张，超限**报错不截断**；媒体原样回去 | 贴一张图能发出去；超限那一下当场被拒，而不是发出去等端点回错 |
| 7 | **两条阈值**：软线越线时问用户一次（自交接 / 独立交接 / 不交接）；硬线越线这次请求不发；交接那一次硬线让路；这道线罩住 subagent 与孙级 | 撞软线时界面出现一道三选题，答「不交接」之后不再问；撞硬线当场被拒，不是发出去让厂商回错 |
| 8 | **关掉再打开**：关闭宿主是显式动作（命令 + 二次确认）；重启之后所有会话都是死的，只有人的话能重新开始；记忆与 inbox 都还在 | 关掉再打开：历史与没被处理的那几句话都在，没有一段会话自己跑起来 |
| 9 | **升级**：宿主验「这一版拿得到」、写 pin、以升级为理由退出，由启动方式把它重拉起来；装包与拉起不在宿主里 | 点一次升级，宿主换到新版；升不上去时说得清是哪一段没成 |
| 10 | **子执行体失败也要到客户端**：subagent 与孙级那次请求失败时，错误事件同样要送达 | 某个 subagent 请求失败，界面上看得出是哪一层、为什么 |
| 11 | **客户端能用**：终端与桌面连得上新宿主，并把上面这些事做完 | 从连接屏走一遍：连上、建项目、建会话、发话、看图、改配置、交接、关掉 |

## 已经拍过、不要重开的

- **每条连接都要凭证，凭证只从握手帧上来。** 不判来路、没有「回环地址免检」：本机的无感来自 `run/token` 里那一串被客户端读走，不是来自地址。对外实例不写那个文件，凭证由 `agents-host token create` 造出来再分发。吊销只影响以后能不能连上，不回头断开已经握过手的连接。
- **凭证不进契约面。** 客户端只有「记住密码 + 连接管理」；创建 / 列出 / 吊销是宿主命令行的事。这条 2026-11-13 拍过一次，重写时又被放回契约面一次 —— 别再放回去。
- **不做任何降级。** 申请哪个执行者就跑哪个，做不成 = 失败：开闸、退出交接状态、告诉用户失败。换成另一个执行者继续，会让一次失败的交接看起来像成功。注意区分：`summary` 作为**调用方显式选的执行者**不是降级（三选一的题面里就有它）。
- **没有旧版本，也没有旧库。** 表由各域的 `*Table(db)` 就地建；形状对不上就把库文件删掉重建。任何形式的版本递进都是在为一个不存在的处境兜底，而它自己的分支（补列、重建索引、判断列存不存在）每一处都是新的出错面。
- **题挂着时不挡发送。** 要不要因为一道没答的题把发送按钮按住，是客户端的事：它手上就有那道题，而宿主只知道「有这么一道题」却不知道界面上用户正打算做什么。`blocking` 仍进载荷——客户端靠它决定该不该按，而不是靠宿主替它拦。
- **交接不接 Skill。** 交接不是一种能力：把交接文档的模板放进用户可编辑的 Skill 目录，等于用户改一次 Skill 就意外改掉交接行为。用 SDK 内置的那份模板。
  连带一件要清：`ConfigManager.bootstrap()` 仍会释放 `<数据根>/skills/handoff/SKILL.md`，而没人读它。一份看起来是配置点、实质是死的文件，比没有它更糟——要么让 SDK 不再释放，要么先记在这里。

## 门禁

- `tsc --noEmit -p tsconfig.test.json` 通过；
- `npx vitest run` 通过，跑的是域内用例（不起端口、不写真实磁盘）；
- `npx vitest run --config vitest.e2e.config.ts` 通过，跑的是真的一套（`src/app.e2e.test.ts`：真端口、真磁盘、真 WebSocket）；
- 提交信息一行标题说清改了什么，正文写「改前 / 改后 / 为什么」。

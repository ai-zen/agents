# 4.6 附件

> 第四部分（新版需求）之六。这一册只讲「贴一张图、发出去」这条路上的事实。

**上限**：一张最多 **20MB**、一条消息最多 **4 张**；超出上限**报错，不截断**（理由：一张截图内联成 base64 常 1~3MB，再多一次请求就是几十 MB）。`[用户]`

**谁提供入口**：**宿主提供上传入口**，粘贴只是客户端那一半；两条路上限与数值一致。`[用户]`

**内容按原样入库**：落库那份就是发给厂商那份，**一个字都不清理**——prompt caching 要的是前后两次请求的前缀逐字一致，清理过就全 miss。段上的 `__asset_id` 只是本地标记，用在客户端回显与换模型、换端点时兜底重建。`[用户]`

**同一张图全机只存一份**：按内容认，不看文件名。`[用户]`

**发出去的那一份按实发模型重建**（文本段在前）：厂商那边的产物是"这一次发送"的产物——能复用就复用、换端点就内联、都不行才上传一次；失败就报失败，不重试、不判失效、不做过期清理；**绝不假成功**，全失败就退回纯文本并说清楚。`[AI]`

**素材什么时候真的被删**：删一条消息、删一段会话只删**引用**；引用归零才删素材与磁盘文件。`[用户]`

**尺寸**：上传时量一次宽高（解 PNG/JPEG 文件头），解不出就是空，不重试、不告警。`[AI]`

## 与旧版的不同

| 事 | 旧版 | 新版 |
|---|---|---|
| 上限管哪条路 | 只约束**粘贴** | **宿主提供上传入口**，与粘贴那条路同一套上限与数值 |
| 入库的内容 | 不涉及 | **按原样入库**，一个字都不清理（prompt caching） |
| 素材清理 | 不涉及 | 删消息、删会话只删引用；引用**归零**才删素材与磁盘文件 |
| 素材尺寸 | 不涉及 | 上传时量一次宽高，解不出就是空，不重试不告警 |

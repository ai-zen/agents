# 四、新版需求（四）：与旧版不同的地方、明确不做、待定

## 4.11 与旧版不同的地方（改口清单）

| 事 | 旧版 | 新版 | 来源 |
|---|---|---|---|
| 改配置 | 重建会话 | **就地刷新**：已有的项目重新发现（MCP 按定义对账、断掉不需要的连接），消息与上下文保留。**理论上不杀任何会话，下一次请求就生效** —— "怎么安全地更新到 agent 上"是待论证的工程问题，不是"换掉/invalidate"一句话 | `[用户]` |
| 界面语言 | 本机偏好文件 | **挂在连接上**，断开即忘，缺省英文；**宿主与客户端各有各负责的多语言部分**，不一刀切 | `[用户]` |
| 装不下时 | 每次都问 | **问一次**；答不要就不再问，聊到撞硬线为止；**没有交互通道就不问**，按默认执行者走 | `[用户] + [旧]` |
| 交接期间投递进来的 | 根本不存在这回事（跑中不许发） | **照收**，只是这一任不取（只关输出闸）；交接一完成就开闸，压着的照原顺序跑 | `[用户]` |
| 交接之后 id 归谁 | **旧 id 给存档、新 id 给接手的那一代**，还要更新「上一轮会话」指针 | **反过来**：id 留在活着的那条，旧记忆单独拿一个存档 id。指针不用改，别人手里的引用也不用改 | `[用户]` |
| 交接之后旧记忆在哪 | 旧会话原样留着（能看、能再打开） —— 这点新版一样 | 还是留成**一段会话**，只是它拿的是**新 id**（见上一行：id 归谁换了边） | `[用户]` |
| 交接那次说的话 | 进 `messages`，可以接着让它细化同一份文档 | **不进记忆** —— 下一代接的是活，不是「关于交接的那场会话」；要打磨就读回项目里那份文件再改 | `[AI]` |
| 问题 | 弹出即走、Esc 跳过 | 当场答，**没有跳过**：不做某个动作本身是选项之一；答完宿主接着把事办掉。**不落库、不跨重启** | `[用户]` |
| 打开时从哪儿接着 | 客户端记住上次 | 客户端记住上次；再加**搜索**（只在桌面端侧边栏，TUI 一阶段不做）与**置顶** | `[用户]` |
| 附件 | 只约束粘贴 | **宿主提供上传入口**，上限与粘贴那条路一致：一张 20MB、一条 4 张、同一张图全机一份（按内容认）；**内容按原样入库**（落库那份就是发给厂商那份，**一个字都不清理** —— prompt caching 要的是前后两次请求的前缀逐字一致，清理过就全 miss）；段上的 `__asset_id` 只是本地标记，给客户端回显与换模型 / 换厂商时兜底 | `[用户]` |
| 附件的发送 | 直传 | 发出的那一份**按实发模型重建**（文本段在前）；厂商那边的产物是"这一次发送"的产物，能复用就复用、换端点内联、都不行才上传一次；失败就报失败 —— 不重试、不判失效、不做过期清理；**绝不假成功**，全失败退回纯文本并说 | `[AI]` |
| 素材清理 | 不涉及 | 删一条消息、删一段会话只删引用；引用**归零**才删素材与磁盘文件 | `[用户]` |
| 素材尺寸 | 不涉及 | 上传时量一次宽高（解文件头），解不出就是空，不重试不告警 | `[AI]` |
| 配置坏了 | 报错 | **直接恢复成出厂配置**并写回，说清哪个文件坏了（本机、项目侧、`~/.agents` 各层一视同仁）；**不去猜怎么坏的、不做精确修复** | `[用户]` |
| 平级会话 | subagent 是同步工具（派它的 agent 等它回一句） | 另开一段**正常会话**：结果靠对方用 `post_message` 投回来；防套娃靠不给 agent 建的会话放创建工具（见 4.6） | `[用户]` |

## 4.13 明确不做

- **不替用户决定要不要交接**：是否自动交接只看自动交接开关。`[用户]`
- **不做账号 / 登录 / 按人分权限，不判来路**：按现有鉴权办；设备不是人，凭证可多串只为单独吊销。`[用户]`
- **杀宿主就是直接杀**：不在关机前"优雅跑完手上这些"；要优雅关机的话另给命令。`[用户]`
- 不提供"还剩多久"：没有百分比、没有预计剩余。但"它在干什么"看得出（见 3.9）。`[AI]`

## 4.14 待定

| 待定 | 现状 |
|---|---|
| **真异步工具**（工具结果靠事件回来） | 机制没定。已立住一条约束：只能挂在常驻 agent 上（一次性跑完就销毁的收不到回话） |
| **用量与花销怎么呈现给用户** | 未谈。**但有一条已经知道是错的**：不能说「一律由客户端算」。客户端手里只有它见过的那些消息（断线重连、按 `after` 增量拉取之后都不全），也不知道历史上每一条消息用的是哪个模型（模型可以换）—— 所以**累计与花销它算不准**。单条 `usage` 是端点回的事实、宿主跟着消息落库（见卷首第 7 条）。合计由谁算、花销要不要按模型单价折算、显示在哪里，等拍 |
| **20MB 与内联上限的缺口** | 一张图允许到 20MB，但有些端点只能内联（更小），于是存在"允许上传、却发不出去"的一档。要不要在上传时就按当前模型提前拒，未定 |
| **一次性的临时请求带图** | 那种跑完就散、不入库的请求没有会话归属，图挂在哪，未定 |
| **删助手时要不要查"还有几段会话在用它"** | 现在只报"默认助手"与"别的助手点名它的函数"两类引用 |
| **「该说而没说」的那批提示** | 删会话 / 删工作区后的确认、撞硬线、撤回后、subagent 结束、附件超限 —— 对应的提示本身仍是缺口 |

## 1.1 产品形状（已过）

**宿主只干三件事**：让 agent 活着、让任何人能投递、让事实可观测。它不产出、不交付"结果"这种物件 —— 谁要结果谁自己看。

**只有一类会话可以等**：一次性会话 —— 同步等结果的 subagent、CLI 的纯 stdio、独立交接的摘要那一路。它们只有一条因果链、没有第二个触发方，所以用 `send` / `runOnce` 等到空闲再返回是安全的。常驻会话永远不满足这个条件（它随时可能被任意触发方从闲推到忙），那里只有投递，没有等。

**一个会话配一个 agent**，agent 就是它的驱动程序。交接是**原地换人**：会话、id、11 格都不动，换的只是"谁在驱动这段记忆"。

**记忆是唯一真相，而且它是 mutable 数组**：没在跑的时候可以直接改（撤回、编辑、交接换记忆都走这条），跑起来的时候不许从外面改。**正常输入只有一条路** —— 走 inbox；用户自己说的话也一样。

**没有段、没有轮、没有圈**。这不是"不许有一次性运行"，而是**不把在做的事描述成段 / 轮 / 圈**：现在的模型是**事件驱动、乱序受理乱序执行**，**某一段消息从不属于谁**；在干什么必须靠**主动观测 agent**、或 agent 主动投递回来，没有谁在报"这是第几轮"。一次性会话有开始有结束，但那个"结束"是它自己的因果链走完了，不是一个"轮"结束了。

**会话之间通信是异步的**：发出去就完了，结果靠对方用 `post_message` 主动通知回来。**通信过程中等待没有意义** —— agent 是事件驱动、一直在跑、中途可能插进各种来源的输入，"我在等某个返回"这件事根本不成立。一切返回，都是对方也发一条 `post_message`。

## 1.2 生死（已过）

**生死全手动**：不自动生、不自动死 —— 没有空闲回收、没有引用计数、没有超时。**将来会有定时器**，但定时器只做一件事：往 inbox 投递。它能吵醒一个本来就活着的会话（闲不闲无所谓），**不能造一个、也不能复活一个**。

**收不收只看一件事：这一刻有没有 agent 实例。** 有就收下进 inbox；没有就直接报错。**任何消息投递本身都不创建、也不复活会话**。能把死会话跑起来的只有人：界面上点发送时先判死活，死的就先调接口复活、再投递。除此以外没有例外：会话之间的 `post_message`、定时器、外部程序，投到死会话一律失败，**吵不醒死者**。**交接期间只关输出闸、不关输入闸**：别人的话照收，排在 inbox 里，交接一完成就开闸接着跑。

**准入是业务的事，不是这套东西的事**：现有鉴权（凭证）本来就够，不区分"人"和"程序"。**不是"我们选择不验"，是根本没有任何业务需要验**；也别为将来预留。

**谁投递的，报错就报给谁。** 宿主不通知、不广播、不记一笔账 —— 由那个 agent 自己跟用户说。

**死的路只有三条**：用户按杀死、用户删掉这段会话、进程退出。**交接不在此列** —— 它是原地换人，换完之后那段会话还是活着的（落在「闲」）。其中只有**按杀死**会让用户没注意到的东西（没消费的条目）悄悄消失。

**删会话＝硬删**，删前警告并把代价说清（消息数、素材数）。

**状态分四件事：闲 / 忙（只读）、输入闸、输出闸、死活。** 闲 / 忙是 agent 此刻在不在活动；两个闸各是开 / 关；「死」= 没有 agent 实例。**「闲」与「输出闸关」必须分得开** —— 一个是不在活动，一个是不取新活。

**暂停与中断是两件事**：暂停按的是输出闸（收话、不动），`abort` 是掐掉在途再加关输出闸。所以引擎上有**只关输出闸**（`pauseOutput()`）与**中断**（`abort()`）；**界面上给的是「继续 ⇄ 中断」一个互切按钮加一个发送按钮，不提供优雅暂停**。**中断不是杀死**：中断完是输出闸关、还能继续；杀死完连 agent 都没了、inbox 作废。

**换掉 agent 不丢 inbox**：交接与换模型都不动会话 id 与 11 格，别人送来的话一句不丢。**交接完成之后是开闸状态**（不记交接前有没有关过闸）；只有按杀死才会把没消费的条目作废。

**inbox 要持久化，界面上要回显** —— 这是"inbox 看得见"的全部含义。

## 1.3 交接与平级会话（已过）

**谁建的，决定自动交接开关的初值**：说的是会话行 11 格里的那一格 —— **「自动交接开关」**。用户建的会话里它**默认关**，装不下时**问一次**要不要交接；答"不要"就**不再问第二次**，继续聊到撞硬线为止。平级会话里它反过来**默认开**，撞线自己交班、不问。

**交接是原地换人，不是新开一段**：会话、id、11 格都不动，换的只有记忆。旧的那份记忆成为**另一段会话**（`已存档_<原名>`）—— 它就是普通会话，能打开、能搜、能删、能接着说，不是"只读存档"这种第二种东西，删除上也不搞任何特例。

**交接期间，界面上拦住人，别处照收**：

- 输入框不能打字、指令也进不来、**没有发送按钮**；只给一个**中断按钮**，作用是**放弃交接、回滚到交接前**。
- 会话之间的 `post_message`、定时器、外部程序投进来的**照常入 inbox**，不拒。
- 交接期间收话照收：它在写文档（忙），别人的话排队；界面照样看得见条数，多了可以 `/free`。
- 写文档的可以是**这段自己的 agent**（自交接），也可以是**另起的一个一次性 agent**（独立交接）；它自己说的话不进这段记忆 —— 否则下一代接手的是"关于交接的那场会话"，不是被交接的活。

**客户端几乎没有变化**：不换窗口、不跳会话、不弹第二个窗口，只是会话列表里多了一条 `已存档_xxx`。

**血缘天然继承**：同一条命，交接不产生新身份，也就不存在"借交接另起一条血缘"这种绕过"只能开一层"的后门。

**交接失败 = messages 回滚到交接前**：记忆还是原来那一份、没多出那段会话。而 **inbox 收到了什么就是什么** —— 交接期间投进来的那些照旧留着，不退回、不作废、顺序不变。告诉用户就行。

**平级会话**是模型另开的一段正常会话：双向可发、结果靠对方 `post_message` 投回来、用户能看能暂停能杀。**防套娃不靠数层数**：agent 建的会话没有创建会话的工具（也没这个权限）。**subagent 不是平级会话**：它是同步工具调用那套原语，界面上是输入框上方的 tabs。

## 1.4 会话上的字段与可改性（已过）

**会话行就 11 格**：id / 名字 / 项目 / 助手 / 模型 / 思考深度 / 交接阈值 / 防护阈值 / 自动交接开关 / 血缘 / 创建更新时间。没有第 12 格。**记忆与 inbox 各自另存**；**状态不是字段** —— 忙 / 闲 / 暂停是 agent 身上的直接状态。

**三种可改性，判据只有一条：进不进 agent 的出厂配置。**

| | 谁 |
|---|---|
| 能改、且不用重建 agent | 名字、自动交接开关、两条阈值（agent 根本不读它们） |
| 能改、但要重建 agent | 模型、思考深度（出厂配置就是"模型 + 它的参数"） |
| 不能改 | 项目、助手 —— 创建即定的身份，改它等于新开一段 |

**思考深度是模型的参数**：换模型时必须清空，否则把一家的 thinking 参数带到另一家会被直接拒。

**改助手定义 = 一次二次确认**：影响面是所有用这个助手的会话，要说人话——"你正在看的这段回答会断"，不是"将重建 agent"。

**两条阈值量的都是「请求前的输入用量」（绝对值）**：交接阈值是软线（到它就触发交接），防护阈值是硬线（**这次请求不发，自己拦下来把话说清**，不是发出去让端点回错，也不是警告放行）。建议硬线 ≈ 软线 × 1.5，但两个数各自可设，不是硬绑。**交接那一次请求也不让路** —— 硬线照旧拦，要避免撞线就把阈值配得够宽（同 [4.2 控制一段会话](05-control.md) 那条 `[用户]` 口径；此前写的「谁设的限谁让路」是旧版的读法，已作废）。

**换掉 agent 不丢 inbox**：交接与换模型都不动会话 id 与 11 格，别人送来的话一句不丢。**交接完成后是开闸状态**（不记交接前有没有关过闸）；只有按杀死才会把没消费的条目作废。

## 1.9 明确不做（用户拍过的不做）（已过）

| 不做 | 依据 |
|---|---|
| 账号 / 登录 / 按人分权限；用凭证区分"人" | 锁定决策（设备不是人） |
| `Origin` 白名单这类来路判断 | 锁定决策 |
| 兼容旧版前端、旧接口保底、迁移或识别旧数据 | 锁定决策 |
| 空闲回收 / 引用计数 / 计时器 | 交接 |
| 客户端管凭证（创建 / 列出 / 吊销） | 锁定决策 |
| 图片模型「恢复出厂」 | 暂时没这个需求，所以也不补对称的方法 |
| **会话内分叉**（同一段会话里从某条消息再分一支，两支并存、可来回切） | 列为后续能力。**不是"另开一段会话"**，也不是"从存档会话接着说" —— 后面那件是那段会话本来就能说话，现在就能做（见 1.3） |
| 跨设备共享「语言偏好」 | 语言是那个客户端自己的事，不跨设备共享 |
| 宿主替用户决定"要不要交接" | 问，而且是**当场问**（题不落库，见 4.5） |
| 按单价折算花销、显示金额 | 用户裁定：不用算钱。用量照旧（客户端按 `messages` 汇总，见卷首第 7 条），不算金额 |
| 问题的持久化、过期与作废状态、全库问题列表 | 用户裁定：持久化太复杂就不做，提问只做实时的 |
| 关机前"优雅跑完手上这些" | 那等于把手动的事变成自动的 |
| 单条回复的"最多多久 / 最多调几次工具"这类上限 | 见 3.7（旧版明写"不设"） |

# 4.4 交接

> 第四部分（新版需求）之四。一段会话装不下时，把班交出去：原会话写出一份交接说明，**这段会话的记忆换成「系统提示 + 断点消息（只带文档路径）」**，然后**原地换人** —— 新 agent 接着往下走。
> 会话本身的组成与生死在 [4.1 会话与记忆](04-session.md)；两条阈值在 [4.2 控制一段会话](05-control.md)。

## 只有一段会话在往前走

**交接不是「新开一段」，是同一条命换了记忆 —— 而旧记忆成为另一段会话。**

- **id 不变。** 还是那段会话、同一个 id —— 侧栏位置、别人手里的引用、上次打开的是哪段，全都不用改指。
- **11 格一个字都不改**：名字、项目、助手、模型、思考深度、两条阈值、自动交接开关、血缘（只有更新时间会动）。换掉的**只有记忆**。
- **旧的那份记忆成为另一段会话**：它有自己的 id、自己的名字（`已存档_<原名>`），出现在会话列表里。**它就是一段普通会话** —— 能打开、能翻、能搜、能删，你说句话它就起来接着聊（从那段记忆往下走，从此是另一条线）。
- **「存档」不是一个类型。** 会话就是一份记忆加一个 id；存档只是「一次交接之前的那个样子」。所以**没有**只读、不能投递、不能叫起来这些特例 —— 那些全是给它另立一套规矩。
- **它的 11 格是抄来的**：项目、助手、模型、思考深度、两条阈值、自动交接开关、血缘都照抄原会话，名字加 `已存档_` 前缀，**只有创建更新时间是交接那一刻**（所以它按自己的时间排在列表里）。`[AI]`
- **所以没有任何东西需要搬**：inbox、名字、开关从始至终没离开过这段会话。
- **血缘跟着走**：那两段本来就是同一条线的前后，血缘不变，也不是模型开出来的平级会话。

**删除上没有存档特例**：删一段会话就是删那一段（不会连坐另一段）；删项目连带删它名下所有会话。`[AI]`

## 谁建的会话，自动交接开不开

| 谁建的 | 自动交接 | 装不下时 |
|---|---|---|
| 用户建的 | **默认关** | **问一次**要不要交接 |
| 平级会话 | **默认开** | 自己交班 |

- 用户选了不交接 → 把选择**记成这段的处理策略**（自动交接开关关掉），继续聊，直到撞上安全线；想改就自己去把开关打开。`[用户]` **目前答案不持久化**，所以会话复活后照样还会问；真要只问一次，得把答案持久化（待论证）。
- **交接失败 = messages 回滚到交接前**：记忆还是原来那一份、没多出那段会话。**inbox 收到什么就是什么** —— 交接期间投进来的照旧留着，不退回、不作废。告诉用户就行。`[AI]`
- **原地交接：交接完成的那一刻新的 agent 就在那儿了**（落在「闲」），不是"停在死格等人叫"。这样它和"不自动生"不冲突 —— 接班是这次交接自己的一部分，不是外面有人把一段死会话叫醒。`[AI]`
- 交接期间攒下的那些话一直待在 inbox 里（一句没搬），**新 agent 一上来就按原顺序取走**，于是它立刻就有活干。`[AI]`

## 交接期间，输入往哪走

**只关输出闸，不关输入闸。** 别人的话照常收进 inbox、排在那儿；交接期间谁都不取，交接一完成就开闸，压着的按原顺序接着跑 —— 该跑就正常跑，全程顺滑。`[用户]`

**界面上**：

- 交接期间**不干扰交接执行**，界面上**唯一的按钮是中断**；没有发送按钮，输入框不给打字。`[用户]`
- 界面上要直说"正在交接"，并说明你的话会交给下一段。

**谁写这份文档，两种写法：自交接与独立 Agent 交接。** `[用户]`

| | **自交接** | **独立 Agent 交接** |
|---|---|---|
| 谁写 | **这段会话自己的 agent**接着写（指令由宿主投进来，它取走这一批就开写） | 另起一个**一次性 agent**，拿当前记忆的副本去写，跑完即散 |
| 为什么不会污染下一代 | 它这一趟的输出落在**即将被替换掉的那份记忆**里；另外这段在交接态下**不落库** —— 所以转录、历史、条数里都不会有它（**但界面照常回显它在做什么**，见下） | 它有自己的空队列，也不属于任何记忆 |
| 别人的话 | 照收进 inbox，但这一任在写文档、不取；下一任按原顺序取走 | 与它无关（它根本读不到这段的 inbox） |

**交接不按住正在跑的东西，只在它闲着的时候发起。** 判据四条，拒因各说各的：没有 agent（`no_agent`）、手上有活（`working`）、输出闸关着（`output_paused`）、已经在交（`handoff_in_progress`）。`[用户]` **空闲时才触发交接的二次确认；那一刻若已经变忙，就下次空闲再实际交接，这次只记下选择。实际交接开始才关输出闸，交接完成即开闸。**`[用户]`

**`/free` 清排队区**：客户端发 `/free`（`agent.clearInbox`）把这一段还没被取走的条目作废。`/clear` 只管清屏，两件事不合成一条命令。`[用户]`

**不落库不等于不回显。** 自交接期间它照常**推事件**（流式、工具、思考都看得见）—— 用户看得见「它正在写」，只是这些消息不进库。中途断线重连的客户端拉一次消息列表就自然看不到它们（库里没有），不需要额外清理。**独立 Agent 交接没有流可看**（文档不是这段会话说的），界面只显示「正在交接」这个状态。`[AI]`

> 这条让旧版一个能力作废：旧版交接那次会话留在 `messages` 里，可以接着让它细化同一份文档。新版每次都是干净的一次性 agent —— **要打磨就让它读回项目里那份文件再改**，文件在那儿，不靠记忆。

**中断 = 回滚到交接前**：messages 回到交接前那一份、没多出那段会话、新的 agent 没有起来；**inbox 收到什么就是什么**（那些话压根没被搬过）。**交接失败不做任何重试**。**中断回滚后保持暂停状态**（输出闸关着）。`[用户]`

## 谁算记忆、谁落库

**「换完之后记忆长什么样」只有 SDK 一处实现**：哪些旧消息留下、哪些标 `omit`、断点消息的形状（`role: system` + `hidden` + 正文只带文档路径）、文档够不够长（不到 **400 字节**算没写出来）—— 这三件事外部使用者用 SDK 时也是同一份，宿主编排用的就是它，**宿主不许再实现一遍**。

**宿主只做「把这份记忆落到库」**：旧记忆挂成另一段存档会话、原会话直接换上新记忆。`[用户]` **交接服务与插件在 SDK 里实现**（别人也要用），**宿主不许搞重复建设**。`[用户]`

- **交接一开始，界面就知道**：从这一刻起输入框不给发、只留中断。怎么表达是接线的事。`[用户]`

## 客户端这时候长什么样

**几乎没有变化 —— 这就是对的。**

- **窗口不动、会话不换、焦点不跳**：交接发生在用户眼前这段会话里。不切换、不重建、不弹第二个窗口、不搞转场动画。`[AI]`（原地交接的直接后果）
- **那段会话本身一个字都没变**：名字、位置（按创建时间排）、状态都照旧 —— 变的只是它里面的记忆。`[AI]`
- **会话列表只多一条**：`已存档_<原名>` —— 它就是那段旧记忆变成的会话，跟别的会话一样在那儿。`[用户]`
- **存档按它自己的时间排**（它就是交接那一刻生成的），不为它特殊插队；要从那段会话**一键跳过去**，不靠列表位置去猜。`[AI]`
- **消息区换成换过之后的记忆**，但**一键能翻回存档**看旧的 —— 用户不该为了看刚才说过的话去别处找。`[AI]`
- **这个会话记忆变了，会话列表多了一个存档会话** —— TUI 与桌面端同一个口径，没有哪边是"跳到新开的窗口去"。`[用户]`
- 它就是一段普通会话，所以搜索照样搜得到、重启之后照样在（顺带一句：这里和"问题只做实时"正好相反，别搞混）。`[AI]`

## 与旧版的不同

| 事 | 旧版 | 新版 |
|---|---|---|
| 装不下时 | 每次都弹三选一 | **问一次**；答不要就不再问，聊到撞硬线为止；**没有交互通道就不问**，按默认执行者走 |
| 交接期间投递进来的 | 根本不存在这回事（跑中不许发） | **照收**，只是这一任不取（只关输出闸）；交接一完成就开闸，压着的照原顺序跑 |
| 交接之后 id 归谁 | **旧 id 给存档、新 id 给接手的那一代**，还要更新「上一轮会话」指针 | **反过来**：id 留在活着的那条，旧记忆单独拿一个存档 id。指针不用改，别人手里的引用也不用改 |
| 交接之后旧记忆在哪 | 旧会话原样留着（能看、能再打开）—— 这点新版一样 | 还是留成**一段会话**，只是它拿的是**新 id**（见上一行：id 归谁换了边） |
| 交接那次说的话 | 进 `messages`，可以接着让它细化同一份文档 | **不进记忆** —— 下一代接的是活，不是「关于交接的那场会话」；要打磨就读回项目里那份文件再改 |
| 交接完要不要恢复交接前的暂停 | 恢复 | **不恢复**：交接完成即开闸；只有中断回滚才停在暂停 |

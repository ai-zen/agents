# 三、旧版需求

> `cli-old-archive` 里**已经在跑**的要求。用户从没说要改的部分，**一样都不许丢**。
> 每条给证据。证据写法：`docs/xxx.md` = `cli-old-archive/docs/zh/xxx.md`；`code:src/...` = `cli-old-archive/src/...`。

## 3.1 工具面

模型必须**能自己动手**，而不是让用户替它跑命令再把结果贴回来。

**文件与目录**：`cwd`（在哪）、`read`（能按范围分批读）、`write`、`edit`（单点替换；空 `oldText` 直接拒）、`batch_edit`（按顺序级联，后一条作用于前一条的结果）、`inspect_file`（勘察结构：行数、字符数、列宽分布、行尾风格，不读内容）、`ls`、`exist`、`glob`（基目录不存在要报错，不静默返回空）、`find_text`、`mkdir`、`rm`、`rename`、`copy`。

**跑东西**：`exec`（超时必填；超时或中断要把整组子进程收干净）、`spawn`（立刻返回，只报"起来了"，不跟踪退出状态）、`sleep`、`download_file`（流式写盘，不删已存在的文件）。

**看与画**：`view_image`（本地路径或网址）、`generate_image`（描述生图；端点只回 base64 时落盘给本地路径）。

**七种按需加载**：`load_skill`、`call_skill_sub_agent`、`load_mcp`、`call_mcp_tool`、`read_mcp_resource`，以及两条取 MCP 任务的（`get_mcp_task_result` 取结果、`cancel_mcp_task` 取消，见 3.3 的任务那一段）。重复加载不是错误（幂等，重复调用跳过）。

**20 种内置工具无条件注册**，能不能用由各工具自己声明：

- `view_image` **只对视觉模型开**（查模型是否支持视觉），非视觉模型拿不到它 —— 不靠运行时反复校验。
- `generate_image` **要有图片模型才开**（没配就没有）。
- 一个工具能不能用，是被**模型**决定的，不是被用户决定的。

**subagent 也是一种工具**：带"可被调用"标记的助手能被别的模型当工具用。

**工具输出上限**（出厂 32768 字符，全局一项，不是工具参数，也不按助手分别设）：

- **落盘 + 警告 + 预览**：`exec`（stdout / stderr 分文件落）、`find_text`、`glob`、`ls` 超限时，全文写进临时目录（每次调用一个独立目录），回给模型的是"警告 + 头尾预览（各 1000 字符）+ 统计 + 怎么缩小范围"。
- **只警告不落盘**：`read` 超限提示改用 `range` 分批读；`inspect_file` 明细超限只给概况。
- **媒体不受这条限**：图片、音频转内容块原样返回。削掉一张图不算省钱，算丢信息。

**多个工具可以同时跑**，等工具时只念还在跑的那几个。

证据：`docs/tools.md` 全文（含 20 种逐条语义、可用性、输出保护）；`docs/mcp.md`（媒体不受上限）。

## 3.2 权限

助手定义上的**四维**：`tools` / `skills` / `mcps` / `subagents`。

- 每维要么**白名单**（`allow: a, b`）要么**黑名单**（`deny: x`），二者互斥；`*` 匹配任意。
- **缺失权限字段 = 四维全拒**，不是全给。默认放行是危险的默认值。
- **被拒的东西对模型完全不可见** —— 不只是调用被阻断。看不见它就不会去编、不会反复试。
- **每个助手的权限独立，父子不继承**。
- **唯一例外**：`call_skill_sub_agent` 派出的技能 subagent 是一次性代理，**沿用调用者的能力**、不再走第二遍过滤，同时剔除"派活"这个动作本身，防止自己派给自己。

证据：`docs/tools.md`「权限模型」；`docs/skills.md`「Skill subagent 与权限」。

## 3.3 门外的世界

**越靠近项目越优先，同名以更近的为准；只发现真实存在的目录**（不存在的目录不等于"空配置"）。

**MCP**：

- 配置是**五层链**：项目 `.mcp.json` → 项目 `.ai-zen/mcp.json` → 项目 `.agents/mcp.json` → 用户 `~/.ai-zen/mcp.json` → 用户 `~/.agents/mcp.json`。
- 其中**只有两层能被界面改**（项目 `.ai-zen/mcp.json`、用户 `~/.ai-zen/mcp.json`），其余以文件为准 —— 在别人的仓库里替人写文件，等于替人改他仓库里的内容。
- 传输三种：**stdio**（命令 + 参数 + 环境变量）、**http**、**sse**（网址 + 请求头）。可禁用。
- **启停即时生效**：停用就断、启用就重连；连接断了要自己退避重连。
- 服务器**描述要给模型看** —— 它得知道"这个服务器是干什么的"才敢连。
- **参数按 shell 风格切分成 argv**（引号与转义要认）。
- **需要登录授权的服务器（OAuth）还没做**：字段留着，配了也连不上，别假装支持。
- **任务（Tasks）**：服务器可以推状态（`notifications/tasks/status`），结果只能按任务 id 去拉（`tasks/result`）。所以它不是一个「结果自己回来」的东西，是**推状态 + 拉结果**两件事：状态到了就投一条进那段会话的 inbox（来源标成系统，带服务器名与任务 id），执行体被叫起来之后自己去拉。`call_mcp_tool` 因此多一个可选的任务参数，工具面多两条（`get_mcp_task_result` / `cancel_mcp_task`），客户端要在能力协商里声明支持任务增强。`taskSupport` 三档照规范走：`forbidden` 照旧同步调，`optional` 与 `required` 都带任务参数发起。投递照 4.1：不创建、不复活会话，那段已经死了就把通知丢掉并记日志。`[用户]`

**Skill**：一个目录一份 `SKILL.md`，**四层**优先级（项目两处、用户两处）。能按需加载进上下文；只有标了"支持 subagent"的才能派活。

**用户自己的工具**：`tools/` 下的脚本也是工具来源（项目一层、用户一层）。

**助手与 subagent 定义**：**一个实体一个文件** —— 能进 git、能手改、能 diff。项目级可以覆盖用户级同名的（`sub-agents/` 与 `agents/` 分开放）。

证据：`docs/mcp.md`（五层链、字段、合并优先级、OAuth 未实现）；`docs/skills.md`（目录与优先级）；`docs/configuration.md`（目录树）。

## 3.4 配置面

**一处管完全部，改完即生效，没有全局"保存"键。**

| 配什么 | 字段 |
|---|---|
| 端点 | 名称 / 地址 / 密钥 / 描述 |
| 模型 | 名称 / 挂哪个端点 / 厂商模型名 / 思考档位表 / 交接阈值 / 防护阈值 / 是否视觉 / 描述 |
| 图片模型 | 名称 / 端点 / 模型名 / 默认尺寸 / 默认质量 |
| 助手与 subagent | 名称 / 标识 / 描述 / 模型 / 提示词 / 四维权限 / 是否自定义；subagent 另有"怎么被调用"的函数形状（函数名 / 说明 / 参数结构） |
| 默认项 | 默认助手 / 全局兜底模型 / 默认迁移模型 / 默认图片模型 / 取名模型 |
| 全局 | 工具输出上限 / 中断策略两项 |

**出厂托管 vs 自建**：模型与图片模型里**没标"这是我自己的"的条目，每次启动与出厂清单对齐并被替换** —— 这样出新模型、改预设能到达老用户。自己建的标了才不被覆盖。**恢复出厂** = 整条换回出厂定义、然后重新归入托管。**端点永远保留用户配置** —— 用户的钱和地址不是我们能改的。

**删东西之前要说清"还有谁指它"**：删端点先看还有没有模型挂在上面；删模型要把指向它的默认项改指或清空；删默认助手要连带清默认。

**多行内容**（提示词、函数说明、参数结构）要能调**系统编辑器**写，保存时即时校验（非法 JSON 被拒且**保留改动**便于重试），内容没改就不写盘。

**中断策略两项**（缺字段或非法值启动时补成出厂）：

- 被中断时，模型已经吐出来的思考与正文**留不留**（出厂：留 —— 下一句接着半截往下说；也可以选不留，不再发给模型）。
- 被中断的那组工具调用怎么归一（出厂：**整组保留并给没拿结果的那些补上原因**，因为"调用了"和"结果"必须配对；也可以选整组出列）。

**这两项只在造 agent 时读，改完要重建才生效。**

**思考档位表**：档位名 → 请求参数补丁，随模型走，两家端点对思考参数的要求不一样、差异全部关在表里。

- **出厂备三张**（openai / zhipu-5.3 / deepseek），想接新端点就照抄一张改名，再在模型上填这个名字。
- 表里没有"关"这一档就是**关不掉**（有的厂商官方就不支持）；**没有表 = 不可调**。
- **选档位那一刻把参数补丁写进定义**（配置即事实），所以事后改表**不追溯**已经选过的人。

**凭据**：端点缺密钥时**首次启动先要密钥**（不报错退出）；会话里能改**当前端点**的密钥，保存后重建会话。纯 stdio 没有交互通道：缺密钥直接报错并以非 0 退出。

证据：`docs/configuration.md` 全文（字段、出厂托管、恢复出厂、删除校验、中断策略、「只在建 Agent 时读取」）；`docs/getting-started.md`（思考档位表、首次配置、`/key`）。

## 3.5 附件

- **上限 20MB/张**；**一条最多 4 张**（理由：一张截图内联成 base64 常 1~3MB，再多一次请求就是几十 MB）。
- 客户端粘贴：**先问剪贴板里有没有图，没有才粘文本**；超限**报错不截断**。
- **媒体原样回去**，不受工具输出上限约束（见 3.1）。

证据：`code:src/clipboard.ts:46`（`MAX_CLIPBOARD_IMAGE_BYTES = 20 * 1024 * 1024`）；`code:src/tui/screens/chat.tsx:96`（`MAX_PASTED_IMAGES = 4`）；`src/i18n/zh.ts:55`（提示文案）；`docs/getting-started.md`（粘贴行为、文本上限 256KB 报错不截断）。

> 注：这两个数在旧实现里管的是**粘贴**这一条路。把它们当成"附件通用上限"、并加上"宿主提供上传入口"是用户后来的裁定（见 4.6）。

## 3.6 交接

**两种触发**：用户自己要求（只写文档 / 写文档并立刻换手），和撞上交接线时的自动触发。两条路走同一套交接。

**两种执行者**：

| 执行者 | 谁写 | 好处 | 代价 |
|---|---|---|---|
| **原会话自己写**（默认） | 原会话停手后在自己的会话里写 | 上下文完整，能用工具核实真实状态 | 多 1~2 次全量请求（钱主要花在输入侧） |
| **独立摘要** | 一次独立的模型调用，喂进去序列化后的历史 | 便宜、确定 | 没有工具、没有原会话现场，保真度低 |

保真**正是交接的意义**，所以默认前者；后者便宜、确定，但保真度低，**只有调用方明确选了它才用它**。**不做任何降级。** 申请哪个执行者就跑哪个，做不成 = 失败：开闸、退出交接状态、告诉用户失败。不会换成另一个执行者继续 —— 那会让一次失败的交接看起来像成功。**反过来永远不发生** —— 那会在最危险的时刻再加一次全量请求。

**这个问题旧版怎么摆的**：三选一 —— 自己写 / 独立摘要 / 不交接，默认高亮「自己写」；按取消等于**跳过本次**（历史不受影响，仍超阈值下次还问）；非交互环境直接按默认执行者走。`[旧]`

**交接回合只放行写这份文档**（工具守卫；与输出闸无关 —— 交接期间不收新件、手上这一批照跑）：

- 拒绝一切改文件类动作（`edit` / `batch_edit` / `rm` / `rename` / `mkdir` / `copy`），**只放行"写这份交接文档"这一个写**（路径归一后相等才放行）。
- 拒绝是**软的**：原因作为工具结果回给模型，它自己转回正题，不把整场交接打断。
- **挡不住 `exec`**（`echo > file` 总能绕过）。它降低的是误操作概率，**不是沙箱** —— 别把它当安全边界宣传。
- **不递归**：交接本身不触发另一次交接。

**文档写在哪、长什么样**：

- 落在**项目里**：`<项目>/.ai-zen/handoffs/<YYYYMMDD-HHmmss>.md`（能跟代码一起审阅、提交）。
- 名字只到秒、**不带会话 id** —— 会话名是人手改的，带上只会更难认。
- 结构由**模板**定，模板在 **Skill 文件**里，不在代码里：💬 会话断点 / 🎯 任务目标 / 📊 当前状态 / ✅ 已完成 / 📋 未完成 / 🧠 关键决策（含走过的死路）/ ⚠️ 约束与偏好 / 📁 文件索引 / 🔔 接手第一步。
- 模板用户没动过就跟版本升级同步覆盖；标了"我自己改的"就永不覆盖；项目里放一份同名 Skill 可以覆盖全局那份。读不到模板时有内置的最小兜底。
- 接手的那一代收到的断点消息**只带路径**，不带正文 —— 读的钱由需要细节的一方付。
- 每次交接**只写一次**，不重新生成、不再摘一遍。

**旧版的 id 归属（新版反过来了，见 4.4）**：迁移那条链是「先存旧会话 → 物理剔除历史、只留系统提示 + 一条只带路径的断点消息 → **分配一个新的会话 id** → 更新「上一轮会话」指针」。所以旧版是「旧 id 归存档、新 id 归接手的那一代」，而且**旧会话必须在剔除之前存好**，否则交接失败就把历史弄丢了。`[旧]`

**没有交互通道就不问**（管道、脚本、重定向）：按默认执行者直接走，不阻塞等输入、不额外输出。没人回得了一个问题的时候，问就是卡死。

**取消必须真的回到交接前**：

- 这一场追加的所有东西（几 KB 的指令、工具结果、回执）**全部截掉**：不出现在转录里、翻历史翻不出来、下一次请求也不再带。（旧版它们是真的进了 `agent.messages` 再被截回去，所以 `/handoff` 可以反复打磨同一份；新版压根不进记忆，见 4.4。）
- 写了一半的文档删掉。不降级、不重试、不换手 —— 留下"已换手"的假象比失败更糟。
- 取消要**显式递到交接里**，不能只靠掐断模型请求：独立摘要那一路根本不属于任何会话回合；自己写那一路被掐断不抛错，于是"用户取消"会被误判成"没写出文档"，然后重试一次、再失败一次 —— 用户以为取消了，实际多烧两次全量请求。
- **有一条线之后不能撤**：文档通过校验、旧会话已存档、新的已经上岗 —— 这是提交点。此后的取消不再回退，否则会留下"旧的已存档、新的已上岗"的第三种状态。（新版里这条线对应的是"记忆已经换过"，见 4.4。）

证据：`docs/migration.md` 全篇（两种执行者、`self` 为什么可靠、文档落点与命名、模板来自 Skill、取消、成本）；`code:src/auto-migrate-confirm.ts:16,68`（非交互不问）；`code:src/handoff-service.ts`。

## 3.7 两条阈值与中断

- **交接阈值（软线）**：请求前的输入用量超过它 → 触发交接。
- **防护阈值（硬线）**：请求前超过它 → **这次请求不发，中断**（不是警告后放行，也不是发出去让厂商回错）。
- 两个都是**绝对值**；文档给的是**建议** `guard ≈ handoff × 1.5`，各自可设。
- **交接那一次请求，硬线让路**（谁设的限谁让路）：交接恰好发生在上下文最满的时候，不让路会被自己的护栏拒掉。阈值本身不动。
- **这道线要罩住所有层级的委派**（subagent、孙 Agent），只护主会话等于没护。被拦下的那一层是**软停**：越界的那个死掉，用户的会话继续。
- **除了这两条用量线，别的上限一个都不设**：不设"最多跑多久"、不设"最多调几次工具"。

证据：`docs/configuration.md`（`tokenThresholds`、两者关系、请求前判定）；`code:src/sub-agent-guard-plugin.ts`（把同一个硬线装到 subagent 上、覆盖全部委派路径、软中断、明写"不设轮次上限，不设工具调用次数上限"）。

## 3.8 两个入口

**交互界面**与**一次性输出**两条路，互不混合：

| 模式 | 什么时候 | 干什么 |
|---|---|---|
| **全屏界面** | 无参数且在交互终端里（或显式指定） | 人用：会话、看状态、按按钮 |
| **纯 stdio** | 带参数，或输入输出被管道/重定向 | 脚本用：答案写 stdout（**零 ANSI、零 emoji、零 spinner**），日志与进度错误走 stderr，退出码说话（成功 0、失败非 0），默认**不落盘**（要存档得明说） |

- 强制进界面时，参数作为首条消息；**不在终端里就直接报错**，不悄悄降级成管道。
- `--new` 明确要求"开新会话、别续接"；在一次性那条路上被忽略（一次调用本就是一次性的）。
- **接着上次聊**：记住"上次是哪段会话"，下次启动自动续接。
- **升级**：在所有发布标签里挑**版本最高的那个**；逐步骤显示进度；装完确认再重启。**远端宿主走同一条路** —— 客户端只挑版本、交代意图、等它回来；装包与拉起归那台机器上的启动方式（见 4.5）。`[用户]`
- **shell 兜底钩子**：装一次之后，终端里敲不出来的那条命令会被转进界面、当首条消息发给模型，并且**总是开新会话**（不往那个目录里原有的长会话追加）。只对 bash / zsh 有效（靠 `SHELL` 判断），别的 shell 明说不支持；重装能把旧钩子升级成新版。钩子带来的可能是 `/opt/bin/foo` 这种以 `/` 开头的命令，所以它**不过斜杠命令解析**。

证据：`code:src/mode.ts`（模式判定与 `--tui` / `--new`）；`code:src/stdio-runner.ts`（stdout 纪律）；`code:src/hook.ts`（install/uninstall/升级）；`code:src/session-pointer.ts`（续接指针）；`code:src/tui/screens/chat-commands.ts:415`（`/update`）；`docs/index.md`。

## 3.9 界面要素

**状态栏按块排**：模型 · 助手 · 思考强度 ｜ 这一次回答的用量 / 累计用量 · 生成速率 ｜ 快捷键（垫底）。窄屏时**整块**换到下一行，不把一块劈成两半。

- **累计必须含所有层级的 subagent** —— 漏了，用户会发现账单比界面大。
- 速率：生成中是近两秒实时值；停下后换成本次平均值（优先用真实输出计数）。

**生成中分阶段说清**：连上了 → 排队 → 在想 → 调工具（带工具名）→ 等工具回来（并行时只念还在跑的）→ 在输出。

**subagent 要能单独看**：出现了哪些、各自什么状态（跑着 / 完成 / 失败，圆点在闪 / 绿 / 红，失败必须显示失败）、点进去能看它自己的思考与工具调用；本次结束栏目自动收起。

**渲染**：工具调用压成一行、参数按 JSON 高亮；正文与思考按 Markdown 着色；围栏代码块按语言高亮并**保留围栏标记**；已经不在上下文里的消息要有迹可循（删除线）。

**单条回答内部顺序恒定**：思考 → 工具调用 → 正文。

**输入**：

- 多行、限高（8 行）、窗口跟光标；像正经编辑器的键位（按词移动、删词、删到行首行尾、kill ring、撤销、暂存草稿、粘贴）。
- `/` 菜单：输入即列候选、继续输入按前缀收敛、`Tab` 补全；未识别的命令指向帮助；回车直接执行高亮项。
- `@` 文件补全：**只把相对路径写进草稿，不把文件内容塞进消息** —— 要读的人自己用工具去读，否则一条消息能撑成巨型请求。数据按需扫（**git `ls-files` 优先**，非 git 才扫盘并排除依赖与构建目录），有条数上限、超时即放弃、十几秒缓存，**第一次问要能立刻回"正在扫"**。
- 输入历史＝这段会话里的用户消息（带图的那条连图一起恢复）。
- 空会话要有欢迎内容；整帧高度稳定、输入框吸底、不许二次折行。
- 防误退出；退出要把终端还回去（关鼠标上报、关 raw mode、恢复光标）；下游管道关了（EPIPE）按正常结束处理，不算错误。

证据：`docs/index.md`（状态栏三块、六阶段、主 subagent 栏目、高亮）；`docs/getting-started.md`（输入键位长段、`/` 菜单、欢迎区）；`code:src/tui/` 下 `phase.ts` / `status-segments.ts` / `token-rate.ts` / `agent-tabs.tsx` / `highlight.ts` / `mention.ts` / `file-index.ts` / `input-editing.ts` / `mouse.ts`。

> 旧版只有**一行会自动消失的提示**（`push(text, level)`，两档 info / error），没有持久化、没有作用域、重启就没了。**持久化与「会话内 / 全局」两档是新增**，见 4.5。

## 3.10 关掉再打开

- 每段会话**实时落盘**为独立文件；记一个"上次是哪段会话"的指针，下次启动自动续接。
- 恢复的是记忆；打开就是上次的样子。

证据：`docs/configuration.md`（`sessions/`、`last-session.json`）；`code:src/session-pointer.ts`。

## 3.11 这几条旧版是反的，别搬回去

| 事 | 旧版是这样 | 用户拍成这样 |
|---|---|---|
| 改配置怎么生效 | 关闭配置中心后**重建会话** | **就地刷新**，实例不变、消息保留 |

| 装不下的交接 | 每次都弹三选一 | **问一次**，答不要就不再问 |

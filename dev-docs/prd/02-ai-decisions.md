# 二、AI 决策（可以推翻）

> 这些是用户给了方向、具体形状由 AI 拆的。**推翻它们的成本通常是改一处代码，不是重开一段会话。**
> 每条给理由与推翻方式。凡涉及引擎内部的，正式口径在 `dev-docs/trd/engine.md`；涉及宿主怎么搭的，在 `dev-docs/trd/`。

## 2.1 引擎（`dev-docs/trd/engine.md`）

| AI 定了什么 | 为什么 | 怎么推翻 |
|---|---|---|
| **常驻会话没有 `send()`**，只有 `push()`（投递）；`send` / `runOnce` 只给**一次性会话**（见 4.1） | 建立在"我去等"上的设计看不见不由我引起的变化：等结束一次就失聪 —— 这一条对**常驻**会话仍然成立；一次性会话只有一条因果链，等它是安全的 | 边界就是"有没有第二个触发方"：拿掉这个前提再谈 `send`，就得先推翻 `TRD 的引擎那一册` §1 |
| `inboxTaken`（取走也是变化）**排在落地之后** | 崩溃在中间时"消息已落、条目还在"是可去重的重复；"条目没了、消息没落"是丢 | 换掉这条次序前先给出防丢的办法 |
| 外循环就是一句 `for await (const batch of inbox.asTakeAll())` —— **队列自己就是 inbox，也是那根信号**（空着时它自己在 `pushRx` 上挂起，不另造唤醒信号）。**不取件的等待有两处：进 `for await` 之前一次，每批处理完之后一次（尾部）**，不在外面再套 while | 外面那次：不在不取件期间开拉；尾部那次：批与批之间不取 —— 不取件期间到达的货就躺在队列里，界面看得到条数、能持久化恢复 | **手上已取出的那批算已经开始**：`pauseOutput()` 从**下一批**生效，不去把它收回 —— 它可能已经落了消息、发过 `inboxTaken`、跑了一半工具，塞回队头只会造成重复落地。要立刻停就用**中断**（4.1）。core 的 `outerLoop()` 按这个改；它注释里"迭代器挂起会把到货那批吞下来"那句是错的（`asTakeAll` 没有内部缓冲） |
| `onOuterLoopStart` **不能拒** | 此刻这批已从队列取出，拒了就没主 | — |
| 三个门（内循环开始 / 工具开始 / subagent 开始）**fail-closed**，其余钩子 fail-open，都报一条失败 | 前三个门是"要不要开始干"的闸，崩了还放行等于没闸 | — |
| 状态拆成**两处**：对外那一格 `state: "working" \| "idle"`（外加一个 `started`：起来了吗）**只由循环的位置决定** —— 循环头设 `working`、循环尾（队列空）设 `idle`；内部那道开关 `isOutputPaused`（`true` = 从下一批起不取件）是另一处，`pauseOutput` / 中断翻上去、`resumeOutput` 翻回来 | 没有"重算状态的函数"，也没有 `working` / `busy` 字段 —— 状态是观测值，不是会话字段。两件事压在一格上必然有一格报不出来（不取件期间投进来的那批照跑，跑完就该报 `idle`，而开关还开着）。「手上没活但队列还压着」不报 `idle`，这一条靠**结构**保住：`idle` 只在循环尾、且队列真空了才声明　**两处各有自己的事件**：`state:working` / `state:idle` 按到达值分名，两道闸另给 `output:paused` / `output:resumed` 与 `input:paused` / `input:resumed`（不再只发一条带 `to` 的 `state`）；这样"等到某一格"就是 `events.promise("state:idle")`，不用再写条件变量 | 若哪天要把两处并回一格，先回来改这条；宿主那边订阅 `state` 的地方要跟着改成这两个名字 + 开关的两个事件 |
| **不取件是一道开关**（`isOutputPaused`：从下一批起不再取），**`abort` 是独立信号**（掐在途），`abort` 必然伴随不取件但反过来不成立 | 停下来的方式有两种：让它在下一步之前停，和立刻把它掐断。混成一个就分不出"翻上开关"与"马上掐断" | 界面只暴露暴力中断（见 4.1）；`pauseOutput`（只是不再取件）留给程序化与内部用 |
| 修复只在外循环开头做；`drop` 是真删并报 `messageRemoved` | 装载后的修尾归引擎，宿主只把库里的行交出来 | — |
| `AgentError` 一个类三个码，同一实例挂 `message.error` 与 `failed` | 一个错只能有一条真相 | — |

## 2.2 宿主与客户端接线

| AI 定了什么 | 为什么 | 怎么推翻 |
|---|---|---|
| 模型解析是**三级链**：会话行 > 助手定义 > 全局兜底；**三级全空报错，绝不静默挑一个** | 静默挑一个会变成"界面写着 A、请求落在 B" | — |
| **三个动作正交**：建会话行（`session.create`）、造活对象（`agent.wake`）、投一条话（`agent.send`，只对活着的执行体）各是一条通道，不许把两件塞进一条 procedure | 塞在一起就逼出「投一条空正文来建行」这种将就：那会让执行体白跑一次请求、历史里多一条空消息 | 要合回去先回答一句：客户端要「只建一段空会话」时走哪条 |
| **没有草稿**：输入框里的内容是客户端的状态，宿主不存草稿 | 草稿要在宿主与客户端各存一份，两份必然漂移 | — |
| 打开会话时**状态与消息同一次取**（可只取一样） | 分两次取会在两次请求之间夹进新消息，也没人愿意为不看的消息付费 | — |
| 推送里凡是承载消息 / 内容，**一律用引擎的原始形状** | 事件里发明简化形状（把内容压成字符串）就是这类错误的活标本 | — |
| **状态栏块由客户端现拼**，宿主只给事实 | 同一批事实存两份，其中一份必然过期（曾经真的冻在打开会话那一刻） | — |
| 投递的拒绝**只有两种**（目标不存在 / 目标是死的），以契约错误码回给投递方；不记账、不重试、不补投 | 拒绝是正常的业务结果；而「投递后还要追一笔账」正是「结果要有人收」的余孽（见硬规矩 5） | — |
| 删模型时，默认指向**只改指到同端点的第一条剩余模型**；同端点没剩的就清空 | 跨端点改指等于把请求发去另一家服务商，那件事得由人决定 | — |
| 模型写入三道校验：端点必须存在、`handoff < guard`、思考档位表必须存在 | 三个都是"写进去就一定跑不起来"的组合 | — |
| **未注入交接服务时不装插件，但推一条警告**，不静默 | 不装是能力缺失，不是正常 | — |
| 交接成功后推**两条**会话变更：这段的记忆换过了；另有一段会话出现（旧记忆变成的那段） | 界面要知道的就是这两件事（见 4.4）；不是"旧的那段已死" | — |
| 换过之后的记忆，第一条用**不展示的 system 消息**承载「交接文档路径 + 摘要」 | 参与模型上下文但不给人看，也不进条数与代价 | — |
| 问题对象的 `blocking` **缺省为"挡"** | 问题就是为"停下来问"而造的 | — |
| 按会话列通知时**只回那段的，把全局的滤掉** | 当时想着"这段的界面只管这段的事" | 用户已把两档定下来（4.5）：全局的在哪儿都看得见。这条按 4.5 改 |
| 推送事件可能早于受理回包：接线层按参数里的会话 id 缓冲，等回包写完再放行 | 否则客户端先收到"开始了"却不知道该挂给谁 | — |
| 单实例探活只 `kill(pid, 0)` | 够用，不额外连端口 | — |
| 升级：宿主**不自装包、不 exec 回自己**，安排一次收尾退出，由**启动方式**重拉 —— 本机与远端同一个道理（远端由那台机器上的启动方式重拉，见 4.5） | 自己替换自己在跑的文件是自找的麻烦 | — |
| 客户端与宿主可共享代码，但**禁止发包**：共享包一律私有、各端打包时内联 | 运行期零依赖，少一层要维护的版本兼容 | — |

## 2.3 产品层的拆法

| AI 定了什么 | 为什么 | 怎么推翻 |
|---|---|---|
| 平级会话问状态**只给"忙不忙 + 最近一句摘要"**，工具说明里写明"别轮询" | 给全量等于把对方的上下文搬进来，token 会炸 | 用户若要求能看全量，就得同时接受这个代价 |
| 附件：厂商那边的产物是**"这一次发送"的产物** —— 能复用就复用、换端点内联、都没有才上传一次；失败就报失败，不重试不判失效不清理 | 厂商 id 会过期 —— 所以落库那份只是「上一次发送的事实」，不是真相；真相在 `assets`，换模型 / 换端点时 `resolveHistory` 按当前模型兜底重建 | — |
| 素材**宽高在上传时量一次**（解 PNG/JPEG 文件头），解不出就是空，不重试不告警 | 客户端要按它排版；为解不出的格式做告警矩阵不值 | — |
| `@` 文件补全的数据**由宿主给** | 远程前端看不见用户机器的目录 | — |
| 升级挑版本 = 在**所有发布标签里挑版本最高的** | "别人说最新的那个"可能是 alpha | — |
| 一次性会话怎么落地（借一个临时 Scope、不入库、不推流式事件）是**实现形状**，但它存在这件事已定（见 4.3 与 1.1） | 三处都在用：同步等结果的 subagent、CLI 纯 stdio、独立交接 | 别再把"要不要留"当悬案 |

## 2.4 工程策略

| AI 定了什么 | 为什么 |
|---|---|
| 发布必须走 `pnpm publish`；一律打 `--tag alpha`，不动 `latest` | `workspace:*` 只有 pnpm 会改写；一个包曾因此带着 workspace 依赖发出去过 |
| 测试文件必须进 `tsc` 检查 | 测试里覆盖一个不存在的 `send()` 也永远调不到，接口被本地壳挡住时类型检查根本不看真身 |
| 失败不许用 `.skip` 换绿 | 要么修好，要么删掉并说明 |
| 新增的每个可选入参、可空返回、防御分支都要答得出"哪个客户端的哪一行会走到" | 答不出来就删 |

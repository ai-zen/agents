# 四、新版需求（三）：平级会话、会话可改性、存量照旧

## 4.6 平级会话

一段会话里的模型，可以另开一段**正常会话**去干活。

> 发话的工具叫 **`post_message`**（跟 `create_session` / `read_session_status` 一样全小写加下划线）—— 别再造 `postMessage` / `send_to_session` 之类的第二个名。

- **平级会话之间通信靠投递消息，禁止等待**。发出去就完了，要结果就靠对方也投一条回来，或自己用工具去查对方状态。`[用户]`
- **双向**：开它的那段能发给它，它也能发回给开它的那段。`[用户]`
- **防俄罗斯套娃**：要区分**哪些会话是 agent 建的、哪些是人建的**（或记血缘关系）；**agent 建的会话没有创建会话的权限（没有对应工具）**，所以不可能自己一层层套下去。`[用户]`
- **谁能给谁投、能复活谁，宿主不做限制**：靠 agent 自己的知识与记忆；血缘只用于展示（看历史显示「由会话 X 创建」）。`[用户]` 血缘到底要不要记，看实际情况。`[AI]`
- 平级会话是一段正常会话：用户能看、能暂停、能杀。`[用户]`
- **投递失败就是正常报错**：错回给投递方（那次工具调用），由它自己决定怎么跟用户说。宿主不广播、不记账、不通知。`[用户]`
- 问状态只能问"它现在忙不忙 + 最近一句说了什么（一小段摘要）"，**绝不能把对方的记忆搬过来**；工具说明里要写明"别轮询"。`[AI]`（见 2.3）

> **subagent 不是平级会话。** 它是另一套原语，别和上面混：subagent 的派遣是一次**同步工具调用**（派它的 agent 停下来等它回一句话，那句话作为工具结果回填），登记在派它的那个 agent 身上、**不入库**，那个 agent 一死或进程重启就一起没了。界面上 **subagent 是输入框上方的 tabs**；平级会话在会话列表里（列表怎么摆待定）。`[用户]`

## 4.7 一段会话能被改的

### 有上游默认、会话可覆盖（四样）

| 改什么 | 默认来自 | 要不要重建 agent | 确认 |
|---|---|---|---|
| 模型 | 助手定义 | **要** | 它忙时二次确认；闲/暂停直接换 |
| 思考深度 | 模型 | **要** | 同上。**换模型时它被清空** |
| 交接阈值 | 模型 | 不用 | 不问 |
| 防护阈值 | 模型 | 不用 | 不问 |

**判据只有一条：改的是不是 agent 的构造参数。** 是就得重建，不是就不用；名字、开关、两条阈值它根本不读，改了当场生效。`[用户]` **但"要重建"不等于"必得杀 agent"**：插件完全可以把参数挂在 agent 上，刷新就是给字段赋值，根本没必要杀 agent —— "怎么安全地更新到 agent 上"是要论证的工程问题，不是"换掉"一句话。`[AI]`

### 本来就在会话上的字段（不存在覆盖谁）

| 改什么 | 要不要重建 agent |
|---|---|
| 名字 | 不用 |
| 自动交接开关 | 不用 |

**全局改**（改助手定义，影响所有用它的会话）：要一次二次确认，把代价说清（正在写的内容会断）。`[用户]` 要不要真的把活着的 agent 全重建，**也不一定** —— 同上，看能不能就地刷新。`[AI]`

**换模型不是杀死**：改配置引起的重建，用户按的是"换模型"，不是"杀死" —— **inbox 里的东西一句不丢**（同 4.4：会话 id 与 11 格都没动）。`[用户]` 重建之后暂停要不要保留，未定。

### 两条线的口径

量的都是**请求前的输入用量（绝对值）**，不是"记忆多长"、不是百分比：

| | 交接阈值（软线） | 安全防护阈值（硬线） |
|---|---|---|
| 到了怎么办 | 触发交接 —— 原地交接，接着往下走 | **这次请求不发，中断** |
| 关系 | **建议**硬线 ≈ 软线 × 1.5；两个数各自可设，不是硬绑 |

- **交接那一次请求也不让路**：硬线照旧拦，要避免撞线就把阈值配得够宽，靠配置留出余量。`[用户]`
- **撞上硬线 = 直接报错**，不是把请求发出去让厂商回错，也不是警告后放行，**不做任何兜底**。`[旧] + [用户]` 所以"用户拒绝交接后继续聊"要读成：聊到撞硬线为止；撞了之后要么交接、要么换模型、要么新开一段。
- **除了这两条用量线，别的上限一个都不设** —— 不设"最多跑多久"、不设"最多调几次工具"。`[旧]`
- **这道线罩住所有层级**；被拦下的那一层是**软停**（那个死掉，用户的会话继续）。`[旧]`

## 4.8 存量的那些，新版照旧

工具面、权限、MCP / Skill / 工具 / 定义的发现与合并、配置面、界面要素、双模式与钩子、恢复 —— **一律按第三部分，不重抄**。`[旧]`（**通知与问题不在此列**：这两件是新版才有的东西，见 4.9 / 4.10）

只有三件事是新版才有的口径，写在这里：

- **agent 要随时知道自己在哪个目录里干活**，不能靠用户每句话提醒；**目录变了它得知道变了**。目录来自项目，不是宿主进程自己在哪儿。（怎么给它 —— 每次追加、还是开头说一次 —— 不是需求。）`[旧]`（旧版有 `CwdTrackerPlugin`）
- **项目连带删会话、目录永不碰、目录不见照常可看** —— 见 1.5。`[用户]`
- **状态栏与"inbox 里还剩多少"由客户端现拼**，宿主只给事实；同一批事实存两份，其中一份必然过期。`[AI]`（见 2.2）

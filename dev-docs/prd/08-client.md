# 4.5 客户端看见什么

> 第四部分（新版需求）之五。这一册只讲宿主与客户端之间的那几样东西：通知、问题、入口与连接。
> 会话自己的恢复（记忆与 inbox 都在、重启后都是死的）在 [4.1 会话与记忆](04-session.md)。

## 通知

通知是一条**独立通道**，**绝不混进消息流**。它分两档作用域：

| | **会话内通知** | **全局通知** |
|---|---|---|
| 属于谁 | 挂在一段会话上 | 不属于任何会话 |
| 在哪儿看得到 | 那段会话里 | **哪儿都看得到** —— 它不属于任何一段，所以任何界面都得给；否则它凭什么叫全局 |
| 装什么 | 与那段有关的事（这段的记忆刚被换过、这段自动起名失败…） | 与整机有关的事（配置文件坏了已恢复出厂、宿主升级了、日志里出了错…） |
| 那段会话被删 | **跟着没** | 留着 |

- **四种语气**：信息 / 成功 / 警告 / 错误。「已保存」这种一秒提示归**成功**档（带很短的持续时间），出错归错误、快出问题归警告。`[用户]`
- **带持续时间**：给秒数就到点自己消失，不给就是永久、只能手动清。重启之后永久的那些还在。
- **清**分三个粒度：清一条、清一段会话的、清全部。清全部要明说，不能顺手全清。
- **警告与错误同时进宿主日志** —— 界面被占着的时候，日志必须另有去处。
- **一次改动合成一条**，不逐条刷屏（提示栏位有限，逐条推会互相盖掉）。
- **语言在产生那一刻就定下来**：落库存的就是当时那句成品句子（产生处套一次 `.t(..)`，之后一路上都是字符串）；用户之后改了语言，旧通知保留旧语言 —— 这是「所有用户可见文本只有一个产生点」的代价，认这个代价。不存「键 + 参数」再等出网时渲染：那要多一层把键与参数找回来的机器，换回来的只是「旧通知跟着变语言」。**宿主与客户端各管各自的多语言部分**，不一刀切。`[用户]`
- 清一条已经不存在的，回「没改动」，不假装成功。
- **投递失败不发通知** —— 那件事只回给投递方（见 [4.1](04-session.md)），宿主不广播。`[用户]` 哪些事该发通知，按实际情况定，这里不列死清单。`[AI]`

## 问题（要用户拿主意的事）

**题不持久化：它只活在内存里。它的生命周期跟连接无关** —— 客户端断开再连回来，照样看得到题；进程没了题就没了。`[用户]`

**题存在的意义是"答完之后触发某件事"，所以要有活着的消费者来消费它** —— 答完该干的事由宿主办掉，客户端不必再发命令。`[用户]` **理由不是「多一张表太贵」，是消费者对不上**：持久化之后再重建，题虽然被答了，却没有消费者了。`[AI]`

**自动交接只看自动交接开关**：开着就不问、它自己交班；关着就问。跟有没有人在场、有没有连接都没有关系 —— **没有客户端照样问**，题就在内存里挂着等人。`[用户]`

### 三道选项，没有"不答"

**自交接**（原会话自己写，默认高亮）/ **独立交接**（另起一次调用写摘要）/ **不交接**。`[用户]`

**题只能被答**：没有「关掉」、没有「跳过」、没有「过期」、也没有「这次不答」—— **不做某个动作本身就是选项之一**（不交接）。题挂着期间它挡着 `session.send`。`[用户]`

- 选「自交接」而它写不出来时：这一趟就是**失败**（开闸、退出交接状态、告诉用户失败），**不做任何降级** —— 不会换成独立交接继续，那会让一次失败的交接看起来像成功；反过来也永远不发生（见 4.4）。`[旧]`
- **选项是值 + 文案键**，不是句子；要用时在产生那一处套 `.t(..)` 渲染成句子，不按连接渲染。`[旧]`
- 答一道已经答过的，回当前状态、不重复执行副作用。`[AI]`

### 选择的后果要落，但目前落不全

**「不交接」= 把自动交接开关关掉**，记成这段的处理策略。`[用户]` **但答案本身不持久化**，所以会话复活后照样会再问；真要"只问一次"，得把答案持久化（待论证）。`[用户]`

**空闲时才触发这道题；答题时若已经变忙，就下次空闲再实际交接，这次只记下选择。**`[用户]`

### 题跟着什么走

- **这段会话死了，题跟着没。** `[用户]`
- 题只在**题还活着、这段会话还在**的范围里挡着会话；题一消失自然不挡。`[AI]`
- 题的状态只有两格：`pending`（挂着等人答）与 `answered`（答了）。`[AI]`
- **不做「全库问题列表」**：客户端不能自己造题，题只由宿主内部产生（撞软线、危险动作确认）。真正的二次确认走「先算代价、再真做」两步（客户端拿代价去问用户）—— 那是**目标口径**，别当成已实现。`[AI]`

## 入口与连接

- **记住上次连接 / 连接屏 / 拉起本机宿主或连远程（地址 + 密钥）** —— 这些都是**客户端的事**，宿主不掺和。`[用户]`
- **本机拉起要看得见进度**（解析版本 → 下载 → 安装 → 起进程 → 连上），**进度不确定**（不去解析下载器吐的字节数），但必须让人知道它没死；失败与取消就地处理（真原因 + 重试 + 退回连接屏），一次性那条路直接报错退出。`[用户]`
- **远端宿主也要能升级**：它与「本机由客户端 `npx` 拉起」是两种部署形状，客户端那侧的动作却一样（挑版本 → 告诉宿主 → 等它回来）。**装包只能发生在宿主那台机器上** —— 宿主不自装包、不 exec 回自己，所以只能由那台机器上的启动方式替它装；没有这条启动方式，远端就没得升。升级失败必须说清（拉不下来 / 那台机器没起来），不许静默，也不许把远端留成「已经关掉了、没人拉、界面还在转圈」。`[用户]`
- **关闭宿主是显式动作**（命令 + 一次二次确认）；**客户端退出不自动关宿主**。`[用户]`
- **找旧会话**：按名字搜、按聊过的内容搜、按项目过滤，命中要能**定位到那条消息**；侧栏按创建时间倒序、可**手动置顶**。搜索是"有搜索框的那个客户端"的事，**终端界面这一版先不做**（它只列出来让人挑）。`[用户]`
- **凭据归宿主**：客户端只做「记住密码」与连接管理，**不提供**创建 / 列出 / 吊销（那是宿主自己的管理动作）。`[用户]`
- 两个入口、`--new`、续接、钩子、升级 —— 存量需求，见旧版需求那一册。

## 与旧版的不同

| 事 | 旧版 | 新版 |
|---|---|---|
| 通知 | 一行会自动消失的提示，两档 info / error，没有持久化、没有作用域、重启就没了 | **持久化**、可带持续时间、四档语气、**两档作用域**（会话内 / 全局） |
| 问题 | 弹出即走，Esc 跳过 | 当场答，**没有跳过**：不做某个动作本身是选项之一；答完宿主接着把事办掉。**不落库、不跨重启** |
| 打开时从哪儿接着 | 客户端记住上次 | 客户端记住上次；再加**搜索**（只在桌面端侧边栏，TUI 一阶段不做）与**置顶** |
| 按会话列通知 | 把全局通知滤掉 | 全局通知**哪儿都看得见**：按会话列时也要带上全局那几条 |

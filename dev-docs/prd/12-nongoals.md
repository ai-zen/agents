# 4.9 明确不做与待定

> 第四部分（新版需求）之九。这一册只装两样东西：用户拍过不做的事，以及还没拍的事。

## 明确不做

- **不替用户决定要不要交接**：是否自动交接只看自动交接开关。`[用户]`
- **不做账号 / 登录 / 按人分权限，不判来路**：按现有鉴权办；设备不是人，凭证可多串只为单独吊销。`[用户]`
- **杀宿主就是直接杀**：不在关机前"优雅跑完手上这些"；要优雅关机的话另给命令。`[用户]`
- 不提供"还剩多久"：没有百分比、没有预计剩余。但"它在干什么"看得出。`[AI]`

## 待定

| 待定 | 现状 |
|---|---|
| **真异步工具**（工具结果靠事件回来） | 机制没定。已立住一条约束：只能挂在常驻 agent 上（一次性跑完就销毁的收不到回话） |
| **用量与花销怎么呈现给用户** | 未谈。**但有一条已经知道是错的**：不能说「一律由客户端算」。客户端手里只有它见过的那些消息（断线重连、按 `after` 增量拉取之后都不全），也不知道历史上每一条消息用的是哪个模型（模型可以换）—— 所以**累计与花销它算不准**。单条 `usage` 是端点回的事实、宿主跟着消息落库。合计由谁算、花销要不要按模型单价折算、显示在哪里，等拍 |
| **20MB 与内联上限的缺口** | 一张图允许到 20MB，但有些端点只能内联（更小），于是存在"允许上传、却发不出去"的一档。要不要在上传时就按当前模型提前拒，未定 |
| **一次性的临时请求带图** | 那种跑完就散、不入库的请求没有会话归属，图挂在哪，未定 |
| **删助手时要不要查"还有几段会话在用它"** | 现在只报"默认助手"与"别的助手点名它的函数"两类引用 |
| **「该说而没说」的那批提示** | 删会话 / 删工作区后的确认、撞硬线、撤回后、subagent 结束、附件超限 —— 对应的提示本身仍是缺口 |
| **重建之后暂停要不要保留** | 换模型或改配置引起的重建，用户按的是"换模型"不是"杀死"；重建后那个输出闸该是开着还是关着，没拍 |

# TRD：包与模块的职责

> 这一册只回答「谁负责什么、谁不许做什么、对外几个面」。字段、签名、表结构留在代码与类型里；
> 不列方法清单，不复制需求。一个包一段，粗到能一眼看完。

## 内核：`@ai-zen/agents-core`

一个 agent 的全部行为都在这里。它由一个对象和若干零件组成：

| 组成 | 职责 |
|---|---|
| `Agent` | 唯一的核心对象：外循环取件、内循环发请求与跑工具、状态（在干 / 闲）、**两道闸（输入闸、输出闸）各带开关与现读**、寿命（起来、收尾、杀死）、事件总线、插件挂载 |
| `AgentContext` | `Agent` 继承的上下文基类：模型客户端、模型名、消息数组、工具表、模型参数 |
| `Inbox` | 唯一的队列：条目形状（带正文的条目与只用来叫醒的「钥匙」）、按批取件、暂停与继续、清空、把存下来的条目放回队列；**条目落成消息内容也只有这一处** |
| `Message` | 一条消息的形状（角色、内容段数组、状态、用量、错误、隐藏标记、委派归属）与构造助手 |
| `Tool` / `ToolCallContext` | 工具的抽象基类；工具调用上下文贯穿「拦截决策 → 执行」 |
| `Tools/CallbackTool` | 用一个回调定义工具 |
| `Tools/AgentToolLazy` | 把一个 agent 当工具：派出去、把它的事件按同一套名字转发到父级、等它回一句话 |
| `applyChunk` | 一片增量就地攒进消息 —— 这件事只有这一份实现 |
| `formatContent` / `Usage` | 内容段过 wire 的字段白名单；用量归因的纯函数 |
| `AbortedMessages` / `AbortedToolRounds` | 被中断的助手消息怎么处置（保留 / 丢弃）；不完整的工具轮次怎么归一（整组保留并补原因 / 整组出列） |
| 修尾 | 外循环开头把外面交来的历史修一遍：半截的消息、缺结果的那组工具调用 |
| `AgentError` | 四个码，每一个描述的是世界里的什么状态（「队列关了」与「输入闸关着」必须分开） |
| 事件与钩子 | 一套事件名；插件钩子；可拒的四个闸 fail-closed、其余 fail-open，统一从一个口派发 |
| `AgentNS` | 名字空间：状态、条目、事件载荷、内容段的类型 |

**严格没有的**：会话与项目、库与任何持久化、网络与凭证、语言与文案、配置文件的读、能力发现（工具、技能、MCP、subagent 定义）。它连自己叫什么名字都不知道 —— 只有一个模型客户端、一个模型名和一堆消息。

**对外的五个面**（没有第六个门）：

1. **观测**：`on()` 订阅事件，旁路，不影响循环；
2. **介入**：`use()` 挂插件，只有那几个闸能拒；
3. **收件**：`push()` 递一条、`restore()` 把存下来的条目放回队列；
4. **两道闸**：`pauseInput()` / `resumeInput()` / `pauseOutput()` / `resumeOutput()` 四条开关，配 `isInputPaused` / `isOutputPaused` 两条现读。输入闸拦的是投递（关着时 `push()` 被挡回来，与「队列已关」是两个不同的错），输出闸拦的是取件（从下一批起不取，手上这批照跑完）；两道闸各有自己的一对事件，不互相冒充。**改这两道闸只有这四条路**；
5. **寿命**：`start()` / `stop()` / `kill()`（收尾与杀死会顺手关输入闸，那是它们自己的后果，不是调用方直接改闸）。

**判据**：把 sdk 与宿主都删掉，内核配一个假模型客户端，仍能跑完一个 agent —— 取件、发请求、收流、跑工具、发事件、回到闲；两道闸各自关一下再开，事件与现读都对得上。

**细的正式口径**在[引擎那一册](engine.md)：它只讲一个类，细是它的本分；但它不复制需求。

## 能力面与运行时：`@ai-zen/agents-sdk`

两半，得分清楚：**能力面**把内核装成一个有本事的 agent；**运行时**让它活着、让它能和别的 agent 说话。今天前者齐了、后者缺 —— 缺的那半是下面三件事共同的底。

### 能力面（已经有）

| 组成 | 职责 |
|---|---|
| `runtime/` | 造与跑一个 agent：`createAgent`（按容器与定义装）、`SdkAgent`（core 的 Agent 加上容器与定义）、`createModel` / `resolveModel`（模型与参数的三级解析）、`completeOnce`（一次性补全）、`HandoffService` + `HandoffGuardPlugin`（交接算法与交接期间只放行写文档的守卫）、`lastPromptTokens`（用量口径） |
| `scope/` | 能力容器：`Scope`（配置、cwd、定义目录、工具表、权限、插件）、`ScopePlugin`（能力来源的形状）、`PermissionEvaluator`（四维权限）、`disclosure`（给模型看的披露） |
| `scope/plugins/builtin/` | 20 个内置工具与输出保护，按「这个模型能不能用」决定装不装 |
| `scope/plugins/skills/`、`subagents/`、`usertools/` | 三类磁盘来源的发现与派活：技能、subagent 定义、用户自己的脚本工具 |
| `scope/plugins/mcp/` | MCP 的三件事：五层合并发现、连接与重连管理、把服务器摊成工具与资源 |
| `scope/plugins/peers/` | 平级会话的**三个工具**：`create_session` / `read_session_status` / `post_message`。它们不自己实现能力，只认一个三方法的端口（`create` 建完立刻回、`status` 现读加最近一句摘要、`send` 投递不等结果） |
| `config/` | 磁盘配置：读写、出厂托管与对齐、恢复出厂、坏文件修复、思考档位表、出厂技能 |
| `crud/` | 定义仓储：一个实体一个文件（助手、subagent） |
| `agent-plugins/` | 装到 agent 身上的插件：自动交接、自动刷新工具、硬线防护、把硬线装到 subagent 上、未知工具提示 |
| `shared/` / `types/` | 日志口、错误、实体仓储基类、内容块小工具；配置与定义的形状 |

### 运行时（已落地，是这一层存在的地基）

三个核心思想各要一处落点，它们共用同一份登记：

- **常驻 agent**：装起来、登记、开跑、收回。一个身份一段会话，活着的登记全仓只有一份；「先唤醒再递话」是两个动作，不合并。
- **事件驱动**：订阅内核交出来的事实并转出去；没有任何人在等的时候，它照样因为一条投递从闲变成忙、跑完自己回到闲；运行时不替调用方等，也不制造「一次运行」这种东西。
- **agent 之间的通信**：`post(身份, 一条话)` 是最小动作 —— 名字跟模型那一侧的 `post_message` 对齐；与「递话」（往某段会话的 inbox 里放一条，`deliver`）不是同一个词：一个说的是寄给谁，一个说的是怎么送到。平级会话那个三方法的端口由它实现 —— 于是三个工具在没有宿主时也能用。

还带两件：**按目录的能力容器**（cwd 到容器一份，按「这个目录上还有几段会话活着」决定拆）与**四个端口**（落库、发新身份、日志、读配置 —— 它自己不做这些，但必须有地方做）。

### 插件只是工具面

`peers` 那三个工具把「模型要能开一段会话、问它忙不忙、投一句给它」写成了模型看得懂的三个接口；它们**不负责**那三个动作本身。谁去开、谁去投、谁记得它活着 —— 归运行时。工具是模型那一侧的形状，运行时是进程那一侧的事实，两者不可互代。

### 判据

不 import 宿主：起一个 agent 并收到完整流；起两个 agent，A 递给 B、B 回话；一段会话开出另一段、双向都通；两段会话共用一个容器、全部结束后容器被拆掉。再把宿主那一侧的端口换成空实现，上面全不变。

**它严格没有的**：库、连接、凭证、语言与用户可见文案、会话行（它只认一个不透明的会话身份）。

## 宿主：`@ai-zen/agents-host`

**负责**：库与表、连接与凭证、客户端杂项（通知、素材、问题、搜索）、用户可见文案与语言、单实例与发现文件、命令行。

**不许**：装 agent、记谁活着、决定能力容器什么时候拆、判配置合不合法、算 MCP 合并、管连接与重连。

| 组成 | 职责 |
|---|---|
| `infra/` | 不懂业务：库（开库、事务）、一行一个 JSON 的表、事件总线、错误、文件操作、路径、版本、发现文件与进程探活 |
| `modules/<域>/` | 一件一件：session、workspace、agent-寿命相关的 procedure、connection、credential、question、notice、asset、handoff 编排、search、config、scope、api、i18n |
| `modules/events.ts` | 推给客户端的事件联合，只有一份 |
| `app.ts` | 唯一装配根：构造顺序就是依赖顺序 |
| `cli.ts` | 命令行入口：起服务、凭证管理、版本 |

**判据**：把宿主换成空实现，sdk 那条判据里的行为一条不变；在宿主里找不出「谁活着」「容器什么时候拆」这两句话。

## 日志：`@ai-zen/agents-logger`

一个进程一个日志文件，零依赖。只由装配根创建，别处只认那个口（`info` / `warn` / `error`）。

**判据**：换掉它不改变任何行为。

## 连接层：`@ai-zen/agents-client`

到宿主的连接：拉起、发现（发现文件与凭证交付文件）、凭证来源、重连。**不发版**，被终端与桌面各自内联进自己的产物。

**判据**：只有它 import 宿主的类型；`sdk` 与 `core` 不 import 它。

> 现状：已对着宿主的 tRPC 契约重写 —— 一条 WebSocket 上跑 `TRPCClient<AppRouter>`，失败的码按宿主自己那八个还原。

## 假端点：`@ai-zen/fake-llm`

OpenAI 兼容的假端点：交给它一条目标消息，它把那条消息本该到达的那一串 delta 放回来。零依赖（只用 `node:http`），谁的测试都能直接用；仓里所有碰到模型的用例都由它代替真模型。

**判据**：不进产物、不进生产依赖图；生产代码里 import 它就是错。

## 分层的四条判据

1. 这段代码里出现「**谁是活的**」「**谁认识谁**」「**什么时候装、什么时候拆**」→ 该在运行时（sdk），不在宿主。
2. 这段代码是为了「**另一个 agent 也要看到**」而在宿主里转了一道 → 该在运行时。
3. 出现 `as unknown as`、或者「造一个假实例满足 sdk 的接口」→ **缺一个端口**；端口该由 sdk 定义、宿主实现。
4. 反过来：这段代码只在「读写文件、写库、转事件、校验凭证、渲染文案」→ 它就该在宿主，别往 sdk 搬。

## 已经错位的七处（与其纠正）

| # | 做到宿主里的 | 今天在哪 | 纠正 |
|---|---|---|---|
| 1 | 登记常驻 agent | `modules/agent/registry.ts` 的存活表与 `add()` 里那句开跑 | 搬进运行时；宿主不再知道谁活着 |
| 2 | 按目录的能力容器与何时拆 | `modules/scope/registry.ts` 的 `aliveSessions` / `disposeAll` / `refreshAll` | 搬进运行时；「这个目录上还有几段会话活着」由它自己记 |
| 3 | 装配（唤醒） | `modules/agent/assembly.ts`：读历史、修尾、写回、取定义、取容器、解析模型、建订阅 | 运行时的 `wake(身份, 恢复材料)`；修尾交回内核在循环开头做，宿主只看事件再落库 |
| 4 | 投递入口与「装配未完成时先收着」 | `modules/agent/delivery.ts` 的那张 `held` 表 | 搬进运行时；有了登记与 `post`，不需要中转站 |
| 5 | 订阅 agent 事件并分发 | `modules/agent/subscription.ts`：写库、推线上、inbox 镜像捆在一起 | 订阅与分发进运行时（别的 agent 也要订阅）；写库与推送留宿主 |
| 6 | 交接编排与一个假实例 | `modules/handoff/service.ts` 的 `as unknown as SdkHandoffService` | sdk 定义那个端口，宿主实现它，强转消失 |
| 7 | 「越线了怎么办」 | `modules/handoff/service.ts` 的 `automaticMode()` 返回 `null` | 策略还给插件；宿主只提供「问用户」这个能力 |

不改的代价有三条：**平级会话做不成**（三个工具在 sdk 里齐了，端口没人实现）；**换个产品就得把这五件事重写一遍**；**第 6、7 处那种硬转与空返回会越来越多**。

## 四个切面在各层的入口

| 切面 | 内核 | sdk | 宿主 |
|---|---|---|---|
| 创造 | `new Agent`（历史作为入参） | `createAgent` + 运行时的 `wake` | 无 —— 它只发新身份 |
| 观测 | `on()` 发事实 | 运行时转出，并让别的 agent 也能订阅 | 订阅 → 写库 → 推线上 |
| 持久化 | 不发，只发事实 | 同内核：只发事实 | **唯一的写库口**；恢复材料由它交给 `wake` |
| 通信 | `push()` 进队列 | `post()` 给另一段会话 | 把客户端来的投递转进去，不解释 |
| 闸 | 四条开关 + 两条现读 | 透传 | 转成 procedure 与线上事件 |
| 寿命 | `start` / `stop` / `kill` | `wake` / 收回 | 转成 procedure |

三层守同一条规矩：**事实从下往上冒，材料从上往下给；中间没有第二处持有同样的东西。**

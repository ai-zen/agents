# TRD：包与模块的职责

> 这一册只回答「谁负责什么、谁不许做什么、对外几个面」。字段、签名、表结构留在代码与类型里；
> 不列方法清单，不复制需求。一个包一段，粗到能一眼看完。

## 内核：`@ai-zen/agents-core`

一个 agent 的全部行为都在这里。它由一个对象和若干零件组成：

| 组成 | 职责 |
|---|---|
| `Agent` | 唯一的核心对象：外循环取件、内循环发请求与跑工具、状态（在干 / 闲）、**两道闸（输入闸、输出闸）各带开关与现读**、寿命（起来、收尾、杀死）、事件总线、插件挂载 |
| `AgentContext` | `Agent` 继承的上下文基类：模型客户端、模型名、消息数组、工具表、模型参数 |
| `Inbox` | 唯一的队列：条目形状（带正文的条目与只用来叫醒的「钥匙」）、按批取件、暂停与继续、清空、把存下来的条目放回队列；**条目落成消息内容也只有这一处** |
| `Message` | 一条消息的形状（角色、内容段数组、状态、用量、错误、隐藏标记、委派归属）与构造助手 |
| `Tool` / `ToolCallContext` | 工具的抽象基类；工具调用上下文贯穿「拦截决策 → 执行」 |
| `Tools/CallbackTool` | 用一个回调定义工具 |
| `Tools/AgentToolLazy` | 把一个 agent 当工具：派出去、把它的事件按同一套名字转发到父级、等它回一句话 |
| `applyChunk` | 一片增量就地攒进消息 —— 这件事只有这一份实现 |
| `formatContent` / `Usage` | 内容段过 wire 的字段白名单；用量归因的纯函数 |
| `AbortedMessages` / `AbortedToolRounds` | 被中断的助手消息怎么处置（保留 / 丢弃）；不完整的工具轮次怎么归一（整组保留并补原因 / 整组出列） |
| 修尾 | 外循环开头把外面交来的历史修一遍：半截的消息、缺结果的那组工具调用 |
| `AgentError` | 四个码，每一个描述的是世界里的什么状态（「队列关了」与「输入闸关着」必须分开） |
| 事件与钩子 | 一套事件名；插件钩子；可拒的四个闸 fail-closed、其余 fail-open，统一从一个口派发 |
| `AgentNS` | 名字空间：状态、条目、事件载荷、内容段的类型 |

**严格没有的**：会话与项目、库与任何持久化、网络与凭证、语言与文案、配置文件的读、能力发现（工具、技能、MCP、subagent 定义）。它连自己叫什么名字都不知道 —— 只有一个模型客户端、一个模型名和一堆消息。

**对外的五个面**（没有第六个门）：

1. **观测**：`on()` 订阅事件，旁路，不影响循环；
2. **介入**：`use()` 挂插件，只有那几个闸能拒；
3. **收件**：`push()` 递一条、`restore()` 把存下来的条目放回队列；
4. **两道闸**：`pauseInput()` / `resumeInput()` / `pauseOutput()` / `resumeOutput()` 四条开关，配 `isInputPaused` / `isOutputPaused` 两条现读。输入闸拦的是投递（关着时 `push()` 被挡回来，与「队列已关」是两个不同的错），输出闸拦的是取件（从下一批起不取，手上这批照跑完）；两道闸各有自己的一对事件，不互相冒充。**改这两道闸只有这四条路** —— 队列本身不接受外部改状态；
5. **寿命**：`start()` / `stop()` / `kill()`（收尾与杀死会顺手关输入闸，那是它们自己的后果，不是调用方直接改闸）。

**判据**：把 sdk 与宿主都删掉，内核配一个假模型客户端，仍能跑完一个 agent —— 取件、发请求、收流、跑工具、发事件、回到闲；两道闸各自关一下再开，事件与现读都对得上。

**细的正式口径**在[引擎那一册](engine.md)：它只讲一个类，细是它的本分；但它不复制需求。

# TRD：宿主的基础设施

> 这一节从需求的第四部分拆出来：它讲的是宿主这台进程该怎么存在（数据根、单实例、端口、凭证、升级），
> 是技术性的要求。

## 4.17 宿主的基础设施

**数据根**（环境变量 `AI_ZEN_DIR`，缺省 `~/.ai-zen`）：一个库、一个素材目录、两份配置、日志与运行期文件都在它下面。

```
<数据根>/
├── ai-zen.db              全机一个库
├── assets/                上传的临时文件与正式素材
├── config.json            用户配置
├── host.json              宿主自己的设置（端口那一档）
├── reasoning-presets.json 思考策略表
├── mcp.json               用户级 MCP 配置
├── agents/  sub-agents/  skills/  tools/  mcp-oauth/
├── logs/
└── run/
    ├── host.json          发现文件：这台机器上谁在服务
    ├── token              本地凭证交付文件
    └── next-version.json  升级 pin：下次该跑哪一版
```

**单实例**：`run/host.json` 是「谁在服务」的唯一真相（pid / host / port / version / local / startedAt）。启动时读它：pid 还活着就连它、不重复监听；pid 已死或文件坏了就清掉再起。探活只 `kill(pid, 0)`。

**监听地址**：本机实例（缺省）只监听 `127.0.0.1`；对外实例（`--public`）监听所有网卡，`--host` 可以显式指定地址并压过 `--public`。

**端口**：启动参数 > `<数据根>/host.json` > 默认 8790。`--port 0` 只在启动参数那一档放行；显式给出但非法报 `config_invalid`；被占用则启动失败退出，不自动换端口。

**凭证**：库里存摘要，明文只在创建那一次出现；可以有多串，只为单独吊销。凭证**不进契约面** —— 创建 / 列出 / 吊销是宿主自己的管理动作（`agents-host token create|list|revoke`，直接开库、不起服务），客户端只有「记住密码 + 连接管理」。

**每条连接都要凭证**：握手时带上令牌，验不过的连接调不到任何 procedure，回 `unauthorized` 之后关掉。令牌不放 URL 查询串（那会进访问日志与浏览器历史）；本机实例把能用的那一串写进 `run/token` 供同机客户端读，对外实例不写它 —— 那台机器上的凭证只能由人当场造出来再分发给要连的设备。吊销是「以后连不上」，不回头断开已经握过手的连接。

**凭证交付**：`run/token` 只是本地交付口，内容带一个末尾换行；文件权限尽力设成 `0600`，但不作为安全保证。文件在、而那串已经吊销或查不到时，启动会造一串新的写回去 —— 否则那台机器就再也连不上自己。

**升级**——三段分工，宿主不自装包、不 re-exec 自己（本机与远端同一条路）：

| 段 | 谁 | 干什么 |
|---|---|---|
| ① 挑版本 | 客户端 | 各 dist-tag 里取 semver 最高 |
| ② 验 + 记 + 请重拉 | 宿主 | 两条判据验「这一版拿得到」→ 写 pin → 以 `reason: "upgrade"` 退出 |
| ③ 拉起 | 启动方式 | 读 pin，`npx -y @ai-zen/agents-host@<pin> serve` |

两条判据：磁盘上的版本已经是目标（就地换过：桌面端、docker、`npm i -g`）；否则问 registry 有没有这个号（`npx` 拉起的宿主，它自己那份永不变化）。都不成立 → 报 `not_available` 且**不退出**，把「这一版不存在」挡在弄死服务之前。

pin 与退出信号必须分开：只有 pin 的话，一次正常关闭之后启动方式会照着老 pin 把服务又拉起来。

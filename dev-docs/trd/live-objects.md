# 运行时活物规范

这份文件管一类东西：**由运行时创造、有身份、有寿命、需要被第三方观察、其状态需要能被恢复的活物。**
今天就是两个 —— 执行体与能力容器。将来同类的东西（比如平级会话上的那个执行体）仍按它评审。

**不套这套的**：库里有表的行（会话、消息、通知、素材）、一次性过程（交接）、连接与提问。它们各有
各的事实：行的规矩是一行一个 JSON、由它自己的域建表；过程不落库、结束即消失；连接只是一条 socket
的登记。它们没有「内存是真相、库只是恢复材料」这一对，硬套只会长出没人走的条款。

代码里不引用本文件。

## 四问

每个活物必须答得出这四个问题，答不全就先别写代码。

| 问 | 要答的内容 |
|---|---|
| 创造 | 谁造它、造完谁持有、什么时候对外可见 |
| 观测 | 一次性读得回来的那份快照是什么；变化通过哪几条事件说出去；订阅者靠什么判出重复与缺口 |
| 持久化 | 它的哪一部分要落库、落库的切点在哪、恢复时拿什么把它装回来 |
| 销毁 | 谁拆它、拆之前的顺序是什么、拆完库里留什么 |

## 五条判据

一、**创造必报事件，且事件先于对外可见。** 顺序固定：造好 → 报出现 → 快照读口才看得见它。
反过来的话，订阅者会先读到一份它还不认识的活物。

二、**快照必须覆盖事件。** 凡是事件里能表达的状态，打开或列出时必须一次给得全。做不到就有洞：
事件丢了，快照补不上，界面上缺一块而且没人发现。

三、**持久化只有切点，没有自选动作。** 活物不认识库：它发事实，第三方订阅、冲刷、恢复。凡是
要落库的东西，都必须有一条对应的事件；凡是能落库的东西，都必须有一个装回去的口（历史作为入参、
未取走的条目走恢复入口）。写了却没有恢复口，那份数据只是包袱。

四、**收尾必须成序。** 销毁的顺序是：报最后一批事实 → 报「我要没了」 → 解订阅 → 作废。之后
这个活物不再发出任何事件。先解订阅再报，订阅者永远不知道自己漏了什么。

五、**内存是真相，库是恢复。** 有活物时读它的内存；没有活物时才读库（那时库就是它的全部）。
读库只发生在恢复那一刻，写库只发生在事件那一刻。

> 加一个字段的判据：事件、快照、落库、恢复四处要一起改。改不到四处，说明这个字段有两份形状。

## 事件

每条事件四件固定的事：

- `type`：发生了什么；
- `seq`：这个活物自己的一条单调序号，从 1 开始 —— 订阅者靠它判重复与缺口，也靠它答「从哪接着写」；
- `at`：时刻；
- 载荷：**当时那个活物的完整一份**，不是差异；归属（哪个活物、哪一层委派、哪次工具调用）一并带上。

事实分三类，持久化的落点不同：

| 类 | 例 | 谁来持久化 |
|---|---|---|
| 发生了 | 新消息、新条目 | 第一次出现时写一行 |
| 变了 | 正文增量、结构性变化、状态翻转 | 订阅者决定写多细（节流窗口是它的策略） |
| 定稿了 | 一条消息的这一版是终版、一趟请求结束 | 必写，此后这条只读 |

没有「定稿」这一类，订阅者只剩两种坏选择：每片写整行，或者只在收尾写一次、然后在进程死掉时丢正文。

## 三个通用规矩

一、**观察是旁路。** 订阅者抛错被隔离，转成它自己的 `observerFailed`，不打断被观察的活物。磁盘满
不能把推理一起打死。

二、**拦截用钩子，观察用订阅。** 能拒的钩子（决定「要不要开始干」的那几个闸）fail-closed、返回
判决；其余一律 fail-open、不返回值、不参与任何判断。两者不许共用一个口。

三、**策略不进下层。** 写多细、多久冲刷一次、事务怎么开，是订阅者的事。活物只提供切点与事实。

## 执行体要提供的切点

| 切点 | 用途 |
|---|---|
| 出现 / 开始 | 登记、界面挂载 |
| 消息：新增 / 变化 / 增量 / 定稿 / 删除 | 写行、节流、最后写一次、删行 |
| 排队区：入队 / 被取走 / 清空 | 入队即落库（「先落库再入队」的落点）、删行、清段 |
| 一趟请求：开始 / 结束 | 开事务、冲刷、结算用量 |
| 请求已发 / 收流结束 | 用量与代价的原料 |
| 工具：开始 / 结束 | 工具轨迹 |
| 委派：开始 / 结束，以及消息事件上的归属 | 子执行体的话分栏；孙级归到哪一栏在这里定死 |
| 状态：在干 / 闲、两个暂停开关 | 状态快照 |
| 拒绝 / 失败 | 拒绝理由、错误事件；委派出去的失败也要带归属转发 |
| 我要没了 | 订阅者在此之后拿不到任何事实 |
| 订阅者自己炸了 | 报给宿主，不动循环 |

## 能力容器要提供的切点

| 切点 | 用途 |
|---|---|
| 出现 / 拆掉 | 谁知道它可用、什么时候可以拆 |
| 能力变化（工具与 MCP 连上、断开） | 界面显示「能用什么」 |
| 配置改完、就地刷新完 | 「启停即时生效」的完成信号，不必让宿主去订阅配置文件 |
| 交接的开始 / 结束 / 失败 | 交接态、文档落点；这一条归能力容器这一侧还是交接那一侧，按它当时在替谁办事 |

## 第三方怎么写

三段，责任全在订阅者：

1. **订阅**：同步回调里只把事实放进内存待写队，不碰磁盘；
2. **冲刷**：在定稿、一趟结束、条目被取走、活物销毁这四个点上写库；
3. **推进**：把同一批事实转成线上的事件推给客户端；落库失败不许把推送也拖住。

## 评审怎么用

- 新增一个活物：先把四问填满，填不满就是还没想清楚；
- 改一个活物：按「四处一起改」过一遍；
- 接入方：只按「三段」写，不读别人的私有状态，不替下层做决定；
- 一个东西如果答不出「它的内存与它的恢复材料分别是什么」，它就不是这套规矩的对象，别往这里塞。

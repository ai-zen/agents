## 🧠 Key Decisions

### 用户这一轮拍死的业务模型（已写进 `REQUIREMENTS.md`，**不要重开**）

- **host 只是 agent 活着的地方**：让驱动者活着、让任何人能投递、让事实可观测。**不提供"结果"这种商品。**
- **一个会话一个 agent，agent 是会话的驱动程序**；`messages` 是唯一真相、就地可变；**对话只是对 agent 与它的 messages 做持久化和恢复**。
- **投递只是往 inbox 塞东西**；用户说的话也永远经过 inbox，没有第二条路。
- **没有「段/轮/圈」**。用户在这一点上多次发火，原话是「没有该死的段概念，我不知道谁加上去的」。任何"一次运行"的对象、进度百分比、预计剩余都不许出现。
- **结果谁要谁自己观测**；跨会话要结果靠**对方用工具发回来**（`send_to_session` 是纯发送，不等、不锚定、不追问）。原来的"回投跟着结算"整块作废。
- **生死全手动**：外部来源投递到死对话 → **拒，不吵醒**；不自动生、不自动死（连空闲回收都不要）。只有"声称自己是人"的投递能创建/复活 —— 靠**声明**，不靠验人（连接与身份用户说"不管"）。
- **投递失败只回给投递方**（工具调用/客户端），**宿主不做任何通知、不广播、不记账**；由那个 agent 自己跟用户说。投递方要知道自己成没成，自己观测。
- **界面四格：死 / 忙 / 闲 / 暂停**（用户先说三格，后补"以及暂停"）。活着的东西必须可查。待办入库就是为了**界面显示它**，所以界面那份必须等于真队列：进队出现、取走消失、清空消失、杀死全没。
- **两种"死"后果不同**：放弃（用户按杀死 → 待办作废、暂停丢失）vs 换手（交接 / 换模型 → 待办转移、暂停跟着走）。
- **交接**：用户建的对话**默认关**自动交接，装不下时**问一次**；答不要就**不再问第二次**，继续聊到撞硬线（用户明确选"甲"）。兄弟会话**默认开**。交接期间投进来的（含用户自己说的话）一律攒着，完成后一起搬给新的；**继承血缘标记**（否则交接成绕过"只能开一层"的后门）。
- **兄弟会话**：只限一层；会话有血缘标记；双向可发；模型之间**没有杀的能力**。
- **两条阈值**（出处 `cli-old-archive/docs/zh/configuration.md`，不是推的）：量的都是**请求前的输入用量（绝对值）**。交接阈值 = 软线（触发交接），防护阈值 = 硬线（**这次请求不发，中断**，不是警告放行）；建议硬线 ≈ 软线 × 1.5；**交接那一次请求硬线必须让路**（谁设的限谁让路）。
- **会话行上的字段就 11 格**：id / 名字 / 项目 / 助手 / 模型 / 思考深度 / 交接阈值 / 防护阈值 / 自动交接开关 / 血缘 / 创建更新时间。记忆、待办各是另一张表；**状态不是字段**。
- **三种可改性**：能改且不重建 = 名字、自动交接开关、两条阈值（驱动者根本不读它们）；能改但要重建 = 模型、思考深度（进了驱动者的"出厂配置"）；不能改 = 项目、助手（创建即定，改它等于新开一段）。**思考深度存在 Agent 级参数里，换模型时被清空**（思考参数与模型强相关）。
- **全局改（改助手定义）= 一次二次确认**，明说"会杀死所有活着的驱动者并重建、正在写的内容会断"。

### 工程决策（已落地、已提交）

- **`send()` 为什么不存在**：一个建立在「我去等」上的设计，看不见不由我引起的变化 —— 等结束一次就失聪，而会话可以被任意别的触发方从闲推到忙。核心表述在 `CORE.md` §1「为什么没有 `send()`」。**这是这次重写的唯一理由，不要重新引入等待。**
- **`runOnce` 是唯一允许等的地方**，因为一次性 agent 只有一条因果链；为此加了 `lifetime` 与"开跑即关收"（第二次 `push` 抛 `closed`）。
- **`inboxTaken` 排在落地之后**：崩溃在中间时"消息已落、条目还在"是可去重的重复，"条目没了、消息没落"是丢。恢复要**按 `messageId` 去重**。
- **外循环用同步 `takeAll()` + 一根唤醒信号，不用 `asTakeAll()`**：迭代器挂起时会把到货那批吞下来，而暂停要求不取件。
- **`onOuterLoopStart` 不能拒**：此刻这批已从队列取出，拒了就没主。
- **发布必须走 `pnpm publish`**：`workspace:*` 只有 pnpm 会改写。`agents-core` 的 `dependencies` 里没有 workspace 项，所以它的 `check-publish-tool` 拦不住 —— `5.0.0-alpha.0` 就这么带着 `"@ai-zen/agents-testing": "workspace:*"` 发出去了，已用 `5.0.0-alpha.1` 修正。发布一律打 `--tag alpha`，`latest` 不动。
- **测试文件必须进 `tsc` 检查**：`ChatRunner` 曾用一个本地 `ChatAgent` 接口把 core 的 `Agent` 挡住，导致 `agent.run()` 之类的调用类型检查根本不看 core；测试里覆盖一个不存在的 `send()` 也永远调不到。现在 host 的 `pretest` 会跑 `tsconfig.test.json`。

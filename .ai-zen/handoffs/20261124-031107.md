## 🧠 Key Decisions

- **名字叫 `providerSessionId` 而不是 `sessionId`**：宿主的会话 id 也叫 session，两者不是一回事（前者是「服务方眼里的这段上下文」，用来做路由与前缀缓存）。用户先否掉了 `contextRef`，说「太怪」。
- **不耦合 `Agent.id`**：我一度提议直接复用 core `Agent` 的 id，用户明确否掉（「不要耦合到 Agent.id 上」）。所以它是独立一格，宿主传会话 id、子 Agent 各自 mint。
- **SubAgent 另建 client**：父子共用一段上下文标识会让服务方的路由与前缀缓存指错地方；重建 client 只是内存对象，不发请求。
- **不录 `reasoningPreset`**：思考档位表只收「官方文档写明怎么传参数」的端点，OpenCode 这边只有 `capabilities.reasoning.effort` 这一格、且各模型档位集合不同，没有请求侧参数的官方说明，宁可不给它挂表。
- **隐私三格（training / zdr / limited_regions）不做**：没有地方展示，模型表只喂请求与选择器；`syncManagedModels` 会整片覆盖用户那份，塞三个没人读的字段只会让配置变大。
- **出厂端点带空 apiKey 与现有三家一致**：openai / bigmodelcn / deepseek 出厂也是空 key，用户给谁填谁用。用户原话「你在担心个蛋，直接录吧」。
- **端点 baseUrl 用 `https://opencode.ai/inference/go/v1`**：官方每模型还给了 `recommended_api` 与各自的 `base_url`（openai / anthropic / google / systemone），实测 `/go/v1/chat/completions` 对 messages 型与 interactions 型也能转，先用一个网关地址。这是个未写进文档的兼容性假设。
- **走过的死路（别重复）**：
  - 想用 v2 的 `Server` 造「会交任务句柄」的假服务器 —— 它出门前就校验 `tools/call` 结果，`{task}` 直接 -32602；只能手搓 raw transport 的假服务器。
  - 想自己写一层 transport 垫片绕过 v2 的 era codec 来支持 2025 线任务 —— 已被官方 `@modelcontextprotocol/ext-tasks` 取代，别再造。
  - 把「出网标识」实现成从宿主一路透传的 `contextRef` —— 语义错了，它是按活 Agent 分配的。

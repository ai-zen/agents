## 🧠 Key Decisions

- **19 条裁定 + D32**（PRD §2 的 L13/L14、D29–D32 与 §4 的能力改写）：凭证只归宿主（客户端只有连接管理与记住密码）；
  本机模式 `npx` 现下现起（devDependencies 写 semver range，构建时注入 `__AGENTS_HOST_RANGE__`）；下载屏阶段式不确定进度；
  `/ws` 是实体入口、启动自动进入；`/shutdown` 一次确认即关；`/back` 主名；搜索只归桌面端；
  **配置坏了恢复出厂**（三份同口径，留残骸 + 一条通知）。
- **删 wire 面 ≠ 删能力**：`credential.*` 从契约面删除，服务层 / 表 / `run/token` / `agents-host token *` 一字未动。
- **`patchMcps` 整层替换是错的形状**：条目读不全时整层写回会覆盖未知字段 ⇒ 改成按 id 的 `saveMcp`/`deleteMcp`。
- **项目侧与 `~/.agents` 的配置文件不恢复出厂**：它们在用户仓库里，恢复出厂等于改人家的 git 内容。
- **死路（别走）**：
  1. 只信注释/类型不查调用方（本轮多次靠 grep 才发现「没人调」）。
  2. 为「理论上的入口」补契约字段 —— 先说出「哪一行会用到」。
  3. 把测试改绿当交付；测不可达分支的用例要整条删。
  4. 两个仓同时跑「起真宿主」的用例会撞 8790（我误判过一次回归）。
  5. 新包刚发就 `pnpm install` —— `minimumReleaseAge` 会静默装旧版；要把版本加进 `pnpm-workspace.yaml` 的
     `minimumReleaseAgeExclude`（该文件被 cli 仓 `.gitignore` 忽略，改动不入库）或把 range 下限抬到修好的版本。
  6. npm 新包有**分阶段发布占位**（`0.0.0-stage`），发布成功后要等几分钟才可见；`latest` tag 不会自动跳到新 alpha，
     要 `npm dist-tag add <pkg>@<ver> latest`。

## ⚠️ Constraints and Preferences

- **四条硬约束（2026-11-13，任意一波都不许违反）**：① 旧代码与旧门禁一律作废（只针对 `cli` 与 `desktop`；
  `cli-old-archive` 与它无关），不许写兼容层、不许 `.skip` 换绿、测旧行为的用例整条删；② 数据结构一律用
  core/sdk/宿主 `wire` 既有形状，不自造再变形；③ 共享代码只做 `private` 包、构建时内联；④ 客户端产物里
  绝不许出现 `openai` 与 `@modelcontextprotocol/sdk`（cli 的 `npm run check:imports`、desktop 的两条护栏）。
- **兜底治理的判据是必要性**（用户 2026-11-14 纠偏）：真实坏输入与外部会失败的动作留着；「走到它的条件不可能发生」的删。
- **`AGENTS.md`**：改东西前先商量、不替用户做决定、不许在代码注释里立规矩；commit 是按用户「每开发一部分就提交」的
  明确要求做的。
- **交互方式**：一次只问一个问题；决策要论证；不接受「为兼容」；产品行为不许自己拍。
- **密钥扫描钩子不许 `--no-verify`**：测试夹具里那串 OAuth secret 要写成 `placeholder-oauth-secret-for-tests-only` 这类占位符
  （本轮踩过两次）。
- **术语**：**host CLI** = `agents-host` 二进制（serve/token/version）；**TUI CLI** = `cli` 仓的 Ink 界面。

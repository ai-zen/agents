## 🧠 Key Decisions

- **两个状态字段而不是一个**：`runStatus` 答「段跑不跑」，`sendStatus` 答「这次 send 的受理走到哪」；钩子是 await 的且属于 send，不属于段。
- **`stopping` 必须存在**：`abort()` 只掐得掉在飞的请求与工具，`run()` 的 async 栈还在跑 reconcile 与收尾钩子。
- **`terminated` 持久、内部永不复活**：只有外部驱动（`send` / `deliver` 调用本身）能解冻；`abort()` **不碰 inbox**（要作废排队就显式 `clearInbox()`）。
- **取件点只有一处**（内循环末，high 先、`!needContinue` 时 low）。
- **agent 常驻（寿命 = 会话）**：用户拍定「inbox 做进 agent，然后复用标准的会话实现做多常驻 agent 交互」；于是**唤醒**（agent 活着）与**复活**（重建 agent）分成两个词，`deliver()` 只唤醒、绝不偷偷复活。
- **Scope 不自动回收**：去掉引用计数与空闲计时，`scopes.dispose` 撞上存活 agent 拒绝（`ScopeBusyError`），不级联。退出判据改成「连接 0 + 无在跑轮次」。
- **配置改动不是生命周期事件**：`config` 改成端口现读，一切配置改动走 `refresh()`；需要换模型客户端的 agent 由 `AgentRegistry.invalidate` 换掉（空闲当场退役、在跑结算时退役）—— 这是「把现状（下一段生效）原样搬到常驻」。
- **不建 `peer_sessions` 表、不做超时**：阶段 1/2 的既有取舍；跨重启语义留给阶段 3，超时要新增计时器、与「没有计时器」的口径冲突。
- **文档只两份**：`PRD.md` 管需求/决策/裁定/契约，`PLAN.md` 管结构/生命周期/时序/落点/波次/欠账；一件事只写一处。

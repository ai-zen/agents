## 🧠 Key Decisions

- **子 Agent 的增量走 `message.delta` 加一个可选字段，而不是新开事件**：它和主线增量是同一件事（core 的 `AgentNS.Delta`），只差「归哪一栏」。新事件会把两条路的分发逻辑复制一份。
- **id 在第一次见到消息时定死**：落库时再分配新 id，会让「流式时推出去的 id」与「重读回来的 id」不同，客户端刷新后会把同一条显示成两条。
- **子 Agent 的消息也边流边写库**（复用 `streamWriteIntervalMs` 200ms 节流）：不写的话，跑的过程中切过去是空白，中途崩了整段丢失。
- **CLI 的 `refreshState()` 只合并 `context` / `thinking`，绝不整份替换**：宿主一轮跑完就把运行器丢了，回拉给的是 `idleRunState` + 本轮 0，整份替换正好把「本轮 tokens」冲成 0，而 `run.assistantMessageId` 还是 `waitForTurn` 的落定判据。这一条我用例钉住了（改成整份替换即红）。
- **状态栏的块归客户端**：宿主拼好的副本只在拉状态那一刻成立，没有刷新通道；八块要的事实各自都在契约里有一份。同理「块名」更早一步已搬回客户端。
- **踩过的坑**（下一个人别重走）：
  1. npm 发布后**读接口滞后几分钟**：`pnpm publish` 报成功后 `npm view` 仍 404，再发一次会回 `409 Cannot publish over previously staged version`，而 `npm stage list` 是空的。判定办法：用 `curl -sI` 看 `cf-cache-status`，并拿本地 pack 的 sha1 跟 registry 记的 shasum 对。宿主的 tarball 约 2–3 分钟可见，CLI 那次**慢了 10 分钟以上**。
  2. `pkill -f "<字面串>"` 会匹配到自己那条命令行（本轮又踩一次，命令把自己杀了）。改用 `ss -ltnp | grep 8790` 取 pid 再 `kill`。
  3. 别对 `agents/packages/host` 跑 prettier（这个包没有 prettier 门禁，会重排全仓）；**cli 有**，改完 cli 必须先 `npx prettier --write`，否则 `test:all` 第一步就红。
  4. 宿主侧测试件 `FakeAgent` 的子 Agent 原本是个裸对象（没有 `events`），宿主新订阅会直接炸；已补 `createEmitter()`，并且假件里要**先 `applyChunk` 再 emit `chunk-parsed`**（与 core 同序），否则消息内容是空的。
  5. 给 `ChatSessionLike` 加方法后，`cli/src/tui/screens/chat.test.tsx` 的假会话必须同步补上，否则渲染期调用会抛。

# 交接

上下文写满时，这套运行时不做摘要压缩。它停下来写一份 markdown，然后把记忆换成「原模板 + 一条指向那份文档的断点消息」。

## 两条阈值

阈值写在模型定义上（`tokenThresholds`），也可以在会话上覆盖：

| 阈值 | 语义 | 谁在读 |
|---|---|---|
| `handoff` | 软线。越过之后，agent 空闲时触发交接 | `AutoMigratePlugin`，比对上一次请求的 `prompt_tokens` |
| `guard` | 硬线。每次请求前比对，越线就拒掉这一次请求 | `ContextGuardPlugin`，在 `onInnerLoopStart` 上返回理由 |

出厂口径是窗口的 40% 与 80%。两条都是绝对值，配置里写多少就是多少，不做倍数换算。硬线之上不再发请求：宁可报错，也不为一次注定失败的请求付费。

会话行上的 `handoffThreshold` / `guardThreshold` 为 `null` 时跟随模型定义。`autoHandoff` 为 `true` 时直接以 `self` 方式交接；不为 `true` 时先问一句，答「不交接」就按那个处置策略继续，不再问。

## 两档

| 档 | 做什么 |
|---|---|
| `swap`（缺省） | 写文档，然后把这段会话的记忆换成新的一份；旧记忆成为另一段存档会话 |
| `document` | 只写文档。记忆、存档会话、agent 的身份都不动 |

只写文档那一档是给「把它当一次导出」用的：交接回合是这段会话真实发生过的事，照常落库。换手那一档在交接期间不落库——那份记忆马上要被换掉，写进去没有意义。

## 两种执行者

| 执行者 | 谁写 | 特点 |
|---|---|---|
| `self`（缺省） | 原 agent 在自己的会话里写 | 上下文完整、可以用工具核实真实状态，产出质量最好；代价是多 1~2 次全量输入 |
| `summary` | 一次独立的模型调用，把序列化后的历史摘要成文档 | 便宜、确定；没有原会话上下文，也没有工具，保真度低 |

两者之间没有自动过渡：申请哪个就执行哪个，做不成就报失败。换成另一个执行者接着做，会让一次失败的交接看起来像成功。

## 一次交接的过程

1. **触发**：撞上软线，或用户显式执行交接
2. **问一次**（只在没指定执行者时）：三选题——`self`、`summary`、不交接。一段会话上同时只挂一道题；已经有题在等，后来的人等的是同一个答复。答「不交接」会被记住，这段会话此后按同一处置策略走，不再问；这一格只在内存里，重启之后会再问一次
3. **进交接态**：这段会话标为正在交接，界面只保留中止
4. **写文档**：agent 停下手上未完成的事，先核实真实状态，再写
5. **换记忆**（`swap` 档）：旧消息出列，新的记忆是「原模板 + 一条断点消息」
6. **收口**：退出交接态，发通知，投一条「去读那份文档」的指令给这一段

第 6 步那条指令的来源标签是 `handoff-resume`，与交接指令本身的标签分开：守卫按后者认「这一批带着交接指令」并据此关输出开关，两者混成一个会让守卫在错的时机动手。

## 交接文档

落在 `<项目>/.ai-zen/handoffs/<时间戳>.md`。写作规则是一条出厂技能（`<数据根>/skills/handoff/SKILL.md`），核心约束：

- 停止推进：不实现新功能、不继续未完成的任务、不顺手修 bug、不重构
- 不许向用户提问、不许讨论方案、不许请求确认
- 只做两件事：核实真实状态，然后写文档
- 只读操作允许（`read`、`ls`、`glob`、`find_text`、`inspect_file`、`cwd`，以及 `git status`、`git diff`、`git log` 这类只读命令）；不许改代码、不许安装依赖、不许提交
- 一次写完；不读大文件；不把长代码贴进文档
- 核实不了的内容必须写 `⚠️ Unverified`，禁止推测

九节，顺序固定：

| 节 | 内容 |
|---|---|
| 对话断点 | 用户最后要什么、你最后交付了什么 |
| 任务目标 | 用户真正要的东西与验收标准，不是做过哪些步骤的清单 |
| 当前状态 | 分支与提交、未提交改动、测试是否通过、端口是否在跑、依赖是否装好 |
| 已完成 | 每一项：做了什么 + 产出路径 + 怎么验证它真的生效 |
| 未完成 | 剩下什么、卡在哪 |
| 关键决定 | 做过哪些取舍、为什么 |
| 约束与偏好 | 用户与本仓的规矩 |
| 文件索引 | 改过哪些文件、各自是什么 |
| 接手第一步 | 下一任应该先做什么 |

文档小于 400 字节算没写出来：只看文件大小，不读内容——「写出来了没有」不需要读懂它写了什么。

## 换完之后

记忆变成「原模板 + 一条断点消息」两截。那条消息是 `role: system` 加 `hidden`：不给人看，但照常进上下文。它只带文档路径，不带全文——需要细节的一方自己去读，内联会让之后每一条请求都携着全文。新记忆里不再写 cwd 消息：目录随时问 `cwd` 工具就行。

旧记忆的去处：

| 场景 | 旧记忆 |
|---|---|
| 宿主（`swap` 档） | 整段挂成另一段存档会话，名字沿用原会话，`nameSource` 为 `handoff`；两条阈值与血缘照抄 |
| 直接用 SDK | 标记 `omit` 留在数组里，不再发给模型，仍然可以回看 |

存档会话在列表里标为存档，不与原会话混淆。原会话继续用同一份身份、同一个 `agentId`；换掉的只是记忆。

## 文档之外的可追溯性

宿主把一次交接落成数据库里的三条记录：

1. 一条只带文档路径的断点消息（旧记忆剔除后留下的那段开头）
2. 一条「交接文档已写到 `<路径>`」的通知
3. 一段 `nameSource` 为 `handoff` 的存档会话行

因此「什么时候交接的、原会话在哪、文档在哪」事后都查得到。

## 取消与失败

- 用户中止：抛 `HandoffAbortedError`，整个交接回合从消息里截掉，本次新建的文档也不留，会话退出交接态。文档已写好且通过校验之后，取消不再生效。不重试、不降级成 `summary`——把「用户中止」当成「模型没写出文档」，会白跑一次全量输入
- 交接没开起来（这段已经在交接、没有活着的 agent、没有模型可指、正在回答别的问题）：只发一条通知。命令早已返回，用户只能从通知里知道原因
- 写文档失败、文档太短：同上，报失败，不换记忆

## 跨工具续接

交接文档是纯 markdown，断点消息只带路径，续接不依赖这套运行时。换一个开发者、换一个编程智能体、换一台机器，读那份文档就能接着做。这是它与摘要压缩的根本区别：那份文档可以打开读、两次交接可以 diff、可以进版本库、可以交给别人审阅。

## 1. 产品是什么

一台电脑上常驻一个后台服务，承载"一段段对话"：它知道每段说到哪儿、存在哪里、属于哪个项目，也管着这个项目能用哪些技能、工具、MCP、模型。用户关掉窗口、换一个前端、换一台设备连回来，看到的都是**同一段对话、同一份历史**。

它说人话（错误原因、提醒、状态说明），并**自己做多语言**；同时把事实以结构化形状给出，不让前端靠解析句子猜原因。

**它提供能力，客户端提供交互**：宿主只保证"这个能力存在"，界面怎么摆是客户端的事。

**两个"CLI"不是一回事，本稿不混用**：

| 名字 | 是什么 | 跑在哪一侧 |
|---|---|---|
| **host CLI** | `agents-host` 这个二进制本身（`serve` / `token create\|list\|revoke` / `version`）。开库直接用，不跑一轮对话 | **宿主侧**（同一台机器上的管理口） |
| **TUI CLI** | 终端里的交互界面（Ink 那套，需求来源 `cli-old-archive` —— 已归档为只读快照，冻结在 tag `pre-split-20261111`） | **客户端侧**（一条连接的另一端） |

本稿里说"客户端"时指 TUI CLI 与桌面端两者；说"宿主"时指那个进程。

## 2. 已定决策（锁定，不重开）

### 2.1 基础决策

| # | 决策 |
|---|---|
| L1 | **远程是一等场景**；不做任何兼容、不留余地：旧前端不保、旧目录旧代码全删、旧数据不迁移不识别；宿主、契约、前端同一版发布 |
| L2 | **对话存 SQLite**；二进制素材（图片/文件附件）落数据根下的 `assets/`，库里只存引用。故"数据只有一个落点"＝**一个数据根**（库 + assets），不是单个文件 |
| L3 | **提醒：手动清 + 持久化**；通知创建时带**持续时间**字段 —— 给秒数则到点自动消失，不设置则永久存在（只能手动清） |
| L4 | **对话寿命不跟连接走**：10 分钟无活动且没在跑才回收；没有活对话也没有连接后进程才退出 |
| L5 | **重连由客户端主动拉**（拉状态 + 按消息 id 拉消息，含流式中那条的部分内容）；**在线时宿主推送**，两者并存 |
| L6 | **id 一律宿主分配**；助手消息的 id 在请求发出**之前**分配 |
| L7 | **项目与助手创建即定；模型与思考档位在会话级、可改、持久化**：一段对话属于哪个项目、用哪个助手，创建时就定死；这一段用哪个模型、哪一档思考存在会话行上，可以改、改了落库（重开重连、重启都还是它）；要改「以后的对话」就去改助手定义 |
| L8 | **生成状态必须完整**：连上 / 等首字 / 在想 / 在输出 / 在生成工具调用 / 在等哪几个工具 |
| L9 | **MCP 是 5 层链**：`<ws>/.mcp.json` → `<ws>/.ai-zen/mcp.json` → `<ws>/.agents/mcp.json` → `<aiZenDir>/mcp.json` → `~/.agents/mcp.json` |
| L10 | **不做 `Origin` 白名单** |
| L11 | **凭证靠复制 + 手动输入**；**可以有多串**（创建时带备注，权限相同，可单独吊销） |
| L12 | **不做账号 / 登录 / 按人分权限**（设备不是人，凭证多串不算破此条） |
| L13 | **凭证只归宿主**：宿主自己管理凭据、决定哪些凭据能访问宿主；**客户端只有「连接管理 + 记住密码」**。这是两件事 —— 所以「创建 / 列出 / 吊销凭证」是宿主侧的管理动作（`agents-host token create\|list\|revoke`），不是客户端能调的接口 |
| L14 | **本机模式靠 `npx` 现下现起宿主**：能用 CLI 的地方一定有 npm，本机宿主不必预先装好。版本口径：CLI 在自己的 devDependencies 里声明宿主的 **semver range**，构建时把这个 range 注入产物，运行期按它去拉「满足范围的最新版」 |

### 2.3 本轮问答定下的

| # | 决策 |
|---|---|
| D1 | **会话有独立名字字段**（id 永不变、宿主分配），用户可改名 |
| D2 | **自动命名**：第一轮对话结束后、用户未改过名字则自动起名；带独立开关；用**"取名模型"配置项**；**原名＝创建时间**，起不出名就保持原名 |
| D3 | **临时对话**：一次请求跑一轮、结果返回后内存清空；无 id、不可 attach、不入库、不进列表；**只借 Scope，与 Workspace 无关** |
| D4 | **升级**：宿主检测版本号，确认升级真的完成（磁盘上的版本已更新）就**立即重启**，不等在跑的轮次；宿主不自装包 |
| D5 | **图片**：宿主提供**上传入口**；上限 20MB/张、4 张/条。**同一张图全机只有一份**（按内容摘要去重：`assets.sha256` 全局唯一，第二次上传在 `asset.begin` 就回既有引用、不再收字节；同一张图贴到两个对话是「一份字节、一行素材、两行引用关系」）；素材的内容由宿主保存并可按 id 取回，**消息里只记我们自己的引用**——内容段上的本地扩展字段 `__asset_id`（`image_url.url` / `file.file_id` 留空；厂商 `file_id`、base64、绝对路径都不进库） |
| D6 | **图片模型保留**（SDK 能力），含默认图片模型 |
| D7 | **`@` 补全**：按需扫描（git `ls-files` 优先，非 git 用 glob 并排除 `node_modules/.git/dist`），20000 条 / 5s 超时 / 15s 缓存；未就绪要说话 |
| D8 | **文案与多语言**：宿主产出文案并**自己做多语言**；**语言挂在连接上**（`hello` 带可选 `language`，断开即忘），缺省用配置的默认语言（英文） |
| D9 | **Workspace 是一等公民**：id 由宿主分配、**cwd 不可变**；一个 Workspace 诞生一个 Scope；一个 Workspace 下可多个对话，对话**复用**该 Scope；搬家＝新 Workspace（无重定位、无自动发现） |
| D10 | **Workspace 的产生**：**只走显式添加**（选个目录加为项目）；普通对话不会因为落在某个目录里就自动生出项目；临时会话不进这条线 |
| D11 | **删 Workspace＝连带删它名下的对话**，删前明说代价；**目录本身宿主永不碰** |
| D12 | **cwd 不存在**：Workspace 与对话照常存在、照常可看；宿主只报"目录已不存在"这个事实，**是否只读由客户端判断** |
| D13 | **侧栏排序**：默认按**创建时间倒序**，可**手动置顶**；活动/打开/改名都不改变顺序 |
| D14 | **一段对话同时只跑一轮**；再来请求直接拒绝并说明"正忙"；中止是用户的显式动作（不排队、不自动打断） |
| D15 | **崩溃恢复**：边流边写，在途消息以 `Aborted` 落库；装载/重启后复用 core 的 `reconcileAbortedToolRounds(fill)` + `reconcileAbortedMessages(keep)` 修复；存储层必须保留 `status`/`omit` |
| D16 | **搜索**：按名称、按聊天内容全文、按 Workspace 过滤（中文分词成本接受） |
| D17 | **删除对话＝硬删**，删除前警告；图片按引用清理（引用关系随消息级联消失，**归零**才删素材行与磁盘文件：别的对话还在用就留着） |
| D18 | **交接/迁移后开一段新对话**（同 Workspace、同助手），内含系统提示 + 交接文档摘要；旧对话完整保留可回看 |
| D19 | **交接文档写进项目**：`<cwd>/.ai-zen/handoffs/` |
| D20 | **换模型拒绝降级**：历史里有图且新模型不支持视觉 → 不允许换，并说明原因；换了模型，这一段会话的思考档位跟着清回「跟随助手定义」（档位是模型的档位） |
| D21 | **配置只能走宿主 API** 读写（校验与生效点都在宿主） |
| D22 | **问题对象**：有状态、有生命周期、可持久化；多端看同一会话看到同一个问题；交接在**对话停下之后**触发 |
| D23 | **越过硬线两端都拒绝**（客户端拒绝、宿主也拒绝），问题对象继续挂着 |
| D24 | **撤回**：撤回到任意用户消息之前，其后消息硬删，被撤回内容回填输入框；**消息分叉列为后续能力** |
| D25 | **端口**：默认端口 + 启动参数 + 配置文件（`<数据根>/host.json`），优先级 参数 > 配置文件 > 默认端口。**保留发现文件 `<数据根>/run/host.json`**（记 pid / 地址 / 端口 / 是否本地）：端口可能被占而退到系统分配的临时端口，客户端只能从这里读到真实地址；单实例判断也只认它 |
| D26 | **连接管理归客户端**：记住上次连接、首次/失败进连接屏、可启动本地服务或连远程（地址 + 密钥）、可更换 |
| D27 | **阈值配在哪＝不问**（属 SDK 的 `AppConfig` 事实：模型级 `tokenThresholds{handoff,guard}`） |
| D28 | **Agent 跑完即回收；Scope 空闲才回收**：agent 每轮结束立即释放，不驻留、不做生命周期保证；Workspace 的 Scope 在**没有任何 agent 依赖**之后、连续空闲 **10 分钟**才回收。Scope 与 MCP 连接同生共死（回收即断 MCP，可能带走 MCP 服务器拉起的外部进程），所以它的回收条件是「没人用」而不是「这段对话闲了」。两者释放都不得丢用户可见状态（模型与思考档位存在会话行上，agent 回收不影响它们） |
| D29 | **关闭宿主是必要需求**：客户端要有显式的「关闭宿主」命令，一次二次确认，确认即关闭。但**客户端退出时不自动关宿主** —— 一台机器一个宿主，可能多个客户端共用 |
| D30 | **切换工作区是必要需求**：工作区是**实体入口**（列 / 选 / 建），不是一个隐式的「当前目录」。启动时自动进入：本机宿主用当前目录（这条糖），远端用「上次进入的那个」，都没有才进选择环节 |
| D31 | **下载进度屏是必要需求**：本机拉起宿主时要有阶段式的进度呈现（解析版本 → 下载 → 安装 → 启动宿主 → 连上），进度**不确定**（不解析下载器的输出）。失败与取消就地处理：给真原因 + 重试 + 折回远程连接屏（Ctrl+C 杀掉下载子进程回连接屏、不退出程序）；一次性（stdio）模式直接报错退出 |
| D32 | **配置文件坏了就恢复出厂**：`config.json` / `host.json` 读不成配置（解析不了、或者解析出来不是对象）时，用出厂配置顶上 **并写回磁盘**，再落一条 warning 通知（说清是哪个文件坏了）—— 不往上抛、也不在两边各折一次。**三个配置文件（`config.json` / `host.json` / `mcp.json`）同一口径：坏了恢复出厂 + 记一笔 warning 通知**，`mcp.json` 不再例外；它坏掉的那份改名留档为 `mcp.json.broken`（同名已在就带时间戳，不覆盖上一份），供人查「原来那些服务器去哪了」 |

## 3. 判定落点的尺子

| 代号 | 含义 |
|---|---|
| **S** | 宿主承接。判据：远程前端**拿不到**这个事实（磁盘、进程内存、数据库），或它必须是"同一份真相" |
| **C** | 客户端自己做。判据：**本机**能力（终端、剪贴板、编辑器、配色、布局、交互），换一台设备本就该不同 |
| **S+C** | 宿主出事实，客户端出表现 |
| **X** | 不要 |

底层理由（后面反复引用）：①远程拿不到 ②一份真相 ③不丢 ④前端不做算术 ⑤**宿主给能力、客户端给交互**。

### 4.2 一段对话的身份

| 编号 | 要什么 | 落点 | 边界 / 依据 |
|---|---|---|---|

| F-B4 | 换这一段会话的模型（存会话行、可改、重开还在）+ 改助手默认模型（影响以后的对话）是**两个动作** | S | L7；两个动作两个入口，不能混 |
| F-B5 | 换助手只改默认，不改造历史；不可用的助手也要列出并说明原因 | S | L7；"藏起来"会让人以为它没了 |

## 6. 代码里几处容易搞错的事实

| 容易记成 | 实际 |
|---|---|
| MCP 是两个作用域、两层 | 合并是 **5 层链**；能编辑的才是 2 个作用域 |
| 附件上限 8MB 一条 | 图片 **20MB/张**、**4 张/条**；粘贴文本 256KB（本机限制） |
| 对话有"名字"和"标题"两种 | TUI CLI 里名字就是 id；名字字段是新加的（D1） |
| 迁移会把旧历史剔掉 | TUI CLI 是 `prune`；本稿改为**开新对话、旧的完整保留**（D18） |
| 通知只有一种 | 三档语气 + 持续时间字段（L3） |
| 子 Agent 不受上下文限制 | 与主 Agent 同源，递归传染到孙级 |
| 图片模型没有使用者 | SDK 能力，本稿保留并补上生成链路（D6） |
